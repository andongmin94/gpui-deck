[`message.rs`](https://github.com/andongmin94/gpui-design/blob/main/crates/base/examples/recipes/message.rs) は、アプリケーションが渡す作成者、時刻のメタデータ、本文を持つ、
読み取り専用のメッセージを 1 つ表示します。既存の GPUI のレイアウトと Typography の Paragraph を合成します。
任意のアクションは、自身の動作を持つ、渡されたコントロールです。

```rust
Message::new(
    "session-note-message",
    "You",
    "Edited 2026-11-10 09:30:00 UTC",
    current_note,
    palette,
)
.action(edit_note_button)
```

ルートはネイティブな Comment セマンティクスを持ち、重複するアクセシブルな名前は持ちません。作成者
と時刻は、読み上げ順に、それぞれ名前付きの Label になり、その後に、
全文がアクセシブルな名前となる Paragraph が続きます。時刻は、呼び出し側が整形した文字列です。
レシピは、日付の解析、タイムゾーンの選択、配信状態の推測、
ライブアナウンスの追加を行いません。メタデータと本文は、フォーカスストップを追加しません。アプリケーションが、
安定した ID と、渡された作成者、時刻、テキストの意味を所有します。

フレームは、範囲が制限された親いっぱいに広がり、縦方向に伸びます。縦に並ぶ作成者/時刻の
メタデータと本文は、長い韓国語や英語のコンテンツも含め、GPUI のテキストレイアウトに従って折り返されます。
本文の明示的な改行は保持されます。本文の切り詰め、固定のコンテンツ高さ、内部のスクロールコントローラーはありません。
長いメッセージは、アプリケーションの既存の ScrollArea に置いてください。`Styled` は、フレームと継承される
メタデータのプレゼンテーションを変更します。Paragraph はパレットのスタイルを保持します。高さは伸びるようにし、
渡すアクションは、利用可能な幅に収まるレイアウトにしてください。アクションは
本文の下に置かれ、その幅と競合しません。`.action(...)` は 1 つの要素を受け取るため、
アプリケーションは既存の Button や、コントロールを含むコンテナーを渡せます。Button は、自身の
アクセシブルな名前、有効状態、ポインター/Enter/Space による起動、通常の
Tab/Shift+Tab による移動を保持します。メッセージには、行全体の起動や選択状態はなく、
アプリケーションがアクションを削除したときのフォーカスも管理しません。

Message は、作成されたコンテンツとその出所を特定します。Marker はコンテンツ間の境界に
ラベルを付け、Item は汎用的なタイトル、説明、末尾のコントロールをまとめます。これらすべての構成で、
アクションの動作は Button が提供します。Message は、別のボタン、入力、フォーカスモデルを
追加しません。Avatar は独立しており、メタデータにすでに名前がある作成者を
繰り返す必要はありません。

どちらの外観でも、Message は Schedule の既存のメモ/プランのペインの下で使われています。本文は
同じ保持された Textarea の状態を読み取り、アプリケーションは最新のローカルの
`InputEvent::Change` の時刻を UTC で記録します。Edit note はその既存の入力にフォーカスし、
それを編集すると、読み取り専用の表示が更新されます。プログラムによる `set_value` は、
その編集イベントを発行しません。編集メタデータが記録されていないコンテンツには、
`Edit time not recorded` が表示されます。入力にフォーカスしたり、録画日を変更したりしても、
編集のタイムスタンプは更新されません。メモが空の場合、
コンシューマーは、メッセージを作り出すのではなく、既存の EmptyState を表示します。ローカルの
編集タイムスタンプは、送信や配信の受領確認ではありません。設定を閉じても、
メモとそのメタデータは保持されます。2 つ目のメモの値、トランスクリプト、トランスポート、
ストリーミングレンダラー、タイムラインの状態はありません。
