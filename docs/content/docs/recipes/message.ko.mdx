[`message.rs`](https://github.com/andongmin94/gpui-design/blob/main/crates/base/examples/recipes/message.rs)는 애플리케이션이
전달한 작성자, 시간 메타데이터, 본문 텍스트로 읽기 전용 메시지 하나를 표시합니다. 기존
GPUI 레이아웃과 Typography의 Paragraph를 조합하며, 선택적인 액션은 자체 동작을 갖는 전달된
컨트롤입니다.

```rust
Message::new(
    "session-note-message",
    "You",
    "Edited 2026-11-10 09:30:00 UTC",
    current_note,
    palette,
)
.action(edit_note_button)
```

루트는 네이티브 Comment 시맨틱을 가지며 반복되는 접근 가능한 이름이 없습니다. 작성자와
시간은 읽기 순서에 따라 각각 이름 있는 Label이며, 그 뒤에 전체 텍스트를 접근 가능한 이름으로
갖는 Paragraph가 옵니다. 시간은 호출자가 서식화한 문자열입니다. 레시피는 날짜를 파싱하거나,
시간대를 선택하거나, 전달 상태를 추론하거나, 라이브 알림을 추가하지 않습니다. 메타데이터와
본문은 포커스 스톱을 추가하지 않습니다. 안정적인 ID와 전달된 작성자, 시간, 텍스트의 의미는
애플리케이션이 소유합니다.

프레임은 크기가 제한된 부모를 채우며 세로로 늘어납니다. 쌓인 작성자/시간 메타데이터와
본문은 긴 한국어나 영어 콘텐츠를 포함해 GPUI의 텍스트 레이아웃으로 줄바꿈되며, 본문의
명시적인 줄바꿈도 유지됩니다. 본문 잘라내기, 고정 콘텐츠 높이, 내부 스크롤 컨트롤러는
없습니다. 긴 메시지는 애플리케이션의 기존 ScrollArea에 넣으세요. `Styled`는 프레임과
상속되는 메타데이터 표현을 바꾸며, Paragraph는 팔레트 스타일을 유지합니다. 높이는 늘어날 수
있게 두고, 전달된 액션에는 사용 가능한 너비에 맞는 레이아웃을 주세요. 액션은 본문 아래에
놓여 본문과 너비를 다투지 않습니다. `.action(...)`은 요소 하나를 받으므로 애플리케이션은
기존 Button이나 컨트롤 컨테이너를 넣을 수 있습니다. Button은 자신의 접근 가능한 이름,
활성화 상태, 포인터/Enter/Space 활성화, 일반 Tab/Shift+Tab 이동을 유지합니다. 메시지에는
행 전체 활성화나 선택 상태가 없으며, 애플리케이션이 액션을 제거할 때 포커스를 관리하지
않습니다.

Message는 작성된 콘텐츠와 그 출처를 식별합니다. Marker는 콘텐츠 사이의 경계를 표시하고,
Item은 범용 제목, 설명, 뒤쪽 컨트롤을 묶습니다. 이 모든 조합에서 액션 동작은 Button이
제공하며, Message는 별도의 버튼, 입력, 포커스 모델을 추가하지 않습니다. Avatar는 독립적이며,
메타데이터에 이미 이름이 있는 작성자를 반복하기 위해 필요하지 않습니다.

두 모양 모두 Schedule의 기존 메모/계획 창 아래에 Message를 사용합니다. 본문은 같은 유지되는
Textarea 상태를 읽고, 애플리케이션은 가장 최근 로컬 `InputEvent::Change` 시간을 UTC로
기록합니다. Edit note는 그 기존 입력으로 포커스를 옮기며, 입력을 편집하면 읽기 전용 화면
표현이 갱신됩니다. 프로그래밍 방식의 `set_value`는 이 편집 이벤트를 내보내지 않으며, 기록된
편집 메타데이터가 없는 콘텐츠는 `Edit time not recorded`를 표시합니다. 입력에 포커스하거나
녹화 날짜를 바꿔도 편집 타임스탬프는 갱신되지 않습니다. 메모가 비어 있으면 소비자 코드는
메시지를 지어내지 않고 기존 EmptyState를 표시합니다. 로컬 편집 타임스탬프는 전송이나 전달
확인이 아닙니다. 설정을 닫아도 메모와 메타데이터는 유지되며, 두 번째 메모 값, 대화 기록,
전송, 스트리밍 렌더러, 타임라인 상태는 없습니다.
