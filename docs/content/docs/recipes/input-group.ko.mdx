[`input_group.rs`](https://github.com/andongmin94/gpui-design/blob/main/crates/base/examples/recipes/input_group.rs)는 기존
컨트롤과 선택적인 앞/뒤 요소를 감싸는 프레임 하나를 제공합니다. 생성자가 컨트롤 자체를
받으므로 네이티브 입력 렌더러, 값, 선택, 입력 인터페이스는 기존 편집기에 남습니다.

```rust
let control = InputBase::new("session-name")
    .role(None::<Role>)
    .semantic_owner::<Input>(input.entity_id())
    .h(palette.control_height)
    .w_full()
    .child(Input::new(&input));

InputGroup::new("session-name-group", control, palette)
    .focused(input.focus_handle(cx).is_focused(window))
    .invalid(name_invalid)
    .trailing(default_name_button)
```

입력의 레이블, 도움말, 필수 상태, 오류 메타데이터를 보존하려면 그룹을 기존 `Field` 안에
두세요. 네이티브 편집기는 `InputBase` 시맨틱 소유자 바로 아래에 두고, 그룹이 그 완성된
컨트롤을 감싸도록 합니다. 그룹이 테두리와 안쪽 여백을 제공하면 컨트롤의 기존 바깥 테두리와
여백은 제거하세요. `CommandInput`도 마찬가지로 직접 전달할 수 있으며, 검색과 입력
시맨틱이 보존됩니다.

기본값은 가로입니다. `.leading(element)`와 `.trailing(element)`는 컨트롤 앞과 뒤에
나타납니다. `.axis(Axis::Vertical)`은 이들을 컨트롤 위와 아래에 둡니다. 예제는 기존
Textarea 아래에 뒤쪽 키보드 힌트를 사용합니다. 각 슬롯은 요소 하나를 받으며,
애플리케이션이 소유하는 컨테이너도 넣을 수 있습니다. 이동 순서는 전달된 앞/컨트롤/뒤
순서를 따릅니다. Tab 순서에서 입력이 액션 버튼보다 먼저 와야 한다면 버튼을 뒤쪽 슬롯에
두세요.

프레임은 Tab 스톱이나 클릭으로 포커스하는 핸들러를 추가하지 않습니다. 전달된 버튼은 자신의
포커스와 콜백을 유지합니다. `focused`와 `invalid`는 테두리 스타일만 바꾸며 invalid가
우선합니다. 네이티브 invalid 메타데이터는 여전히 Field가 담당합니다. 어떤 애드온을 활성화할지는
애플리케이션이 선택합니다. 예제에서 Use default는 세션 이름이 비어 있을 때만 나타나며,
입력을 편집할 수 없으면 비활성화됩니다. 액션이 실행되면 기존 입력 상태가 `MiniCast`를 받고
포커스를 되찾습니다. 레시피는 두 번째 텍스트 값을 만들거나 자식 요소로부터 수정 권한을
추론하지 않습니다. `Styled`로 프레임을 재정의할 수 있습니다.
