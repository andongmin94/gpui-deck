[`sheet.rs`](https://github.com/andongmin94/gpui-deck/blob/main/crates/base/examples/recipes/sheet.rs) は、既存の Dialog の
コンテンツを、選んだウィンドウの端に表示します。デフォルトは全高の右パネルです。

```rust
Sheet::new("session-settings", &dialog, &fields_scroll, "Session settings", palette)
    .side(SheetSide::Right)
    .description("Choose the session's drawing and toolbar settings.")
    .child(form_fields)
    .footer(
        DialogClose::new(&dialog)
            .trigger(|button| button.child("Done")),
    )
```

閉じている間も、Sheet は `gpui_deck::Root` の下にマウントしたままにしてください。アプリケーションは、
渡した `Entity<DialogState>` と `ScrollHandle` の両方を所有し、保持します。
初期フォーカスはその既存の DialogState で設定し、その `open` と
`close` メソッドを使用します。Dialog は引き続き、モーダルのフォーカスの封じ込め、Escape と
背景による解除、フォーカスの復帰を担います。Sheet は、開閉状態や選択モデルを追加しません。
そのタイトルと任意の説明が、可視のヘッダーと、下にある
Dialog のアクセシブルな名前と説明の両方を提供します。

希望する幅は `palette.dialog_width` で、ビューポートの幅に制限されます。
デフォルトのポップアップはビューポートの高さいっぱいに広がり、角は直角で、
左端に 1 本の罫線を使用します。ヘッダーと任意のフッターは、1 つの
縦方向の ScrollArea の本体の外にあります。各 `.child(...)` はその本体に入り、本体の余白、
間隔、スクロールバーの色はコンシューマーのパレットから決まります。本体は
残りの高さを占め、アプリケーションが保持するスクロールハンドルを使用します。
再び開いたときは、初期フォーカス対象のネイティブな表示により、そのオフセットが調整されることがあります。
コンシューマーは、ヘッダーとフッターを合わせたコンテンツを、
ビューポートの高さ内に収める必要があります。長いフォームのコンテンツは、スクロールする本体に置いてください。

端を選ぶには `.side(SheetSide::Left | Right | Top | Bottom)` を使用します。左/右は
高さいっぱいに広がり、希望する幅として `palette.dialog_width` を使用します。上/下は
幅いっぱいに広がり、そのトークンを希望する高さとして使用します。どちらの寸法も
ビューポートで上限が設けられます。`Styled` による上書きは、端ごとのデフォルトの後に適用されるため、
ビルダーの順序にかかわらず、`.w(...)` は縦方向のパネルの希望する幅を、`.h(...)` は
横方向のパネルの高さを変更します。ビューポートの上限と flex レイアウトは維持してください。どの辺でも、
同じ固定のヘッダー/フッターとスクロールする本体を保ちます。ドラッグ操作とトランジションの
アニメーションは、このレシピの外にあり、ドラッグのインタラクションは Drawer が担います。

カタログの Forms セクションは、保持された 1 つの DialogState と ScrollHandle を使って、
4 つすべての辺から現在のセッションのヘルプを開きます。閉じると、選んだトリガーが
復元されます。ヘルプのテキストとセッションの値は、アプリケーションが所有したままです。

アプリケーションは、`DialogClose` とその無効状態を含め、フッターのコントロールを用意します。キーボードの操作は、
渡されたコントロールと Dialog の既存の Tab の封じ込めに任されます。ScrollArea は、
有効な軸でフォーカスされた子孫を表示し、ネイティブのポインターによるスクロールを提供します。独立した
スクロールのフォーカス対象やスクロールキーのバインディングは追加しません。

どちらの外観も、既存の Session settings フォームに Sheet を使用するようになりました。
サンプルは、その DialogState、名前入力への初期フォーカス、本体のスクロールハンドル、
Preferences/Help/Schedule/Presets の各セクション、Done のバリデーションルールを再利用しています。Compact は、
22 rem の Sheet の中で TabList/Tab/TabPanel を維持します。Settings は希望する幅を 46 rem とし、
選択された名前付きの Region とともに Sidebar を使用します。どちらの幅も
ビューポートで上限が設けられます。より広いプレゼンテーションでは、ナビゲーションとフォームのコンテンツが
並んで収まる余裕があります。閉じて再び開いても、同じ入力、選択、
テーブルの状態が維持されます。既存の Edit の
トリガーとメニュー/コマンドのアクションがその状態を開きます。レシピは、別個の
選択を追加しません。Avatar と AspectRatio は、引き続き HoverCard のプレビューで、保持されているプリセットを描画します。Search commands と Reset preview は、
中央に置かれる Dialog と
AlertDialog のプレゼンテーションを維持します。
サンプルは、遅延描画される Select、Combobox、Calendar、Help のポップアップの幅にも、
ウィンドウに対する上限を設けています。これらのサーフェスは Sheet の幅の上限を継承しません。
