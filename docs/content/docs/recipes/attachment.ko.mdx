[`attachment.rs`](https://github.com/andongmin94/gpui-deck/blob/main/crates/base/examples/recipes/attachment.rs)는 파일의
이름, 미디어 유형, 크기를 애플리케이션이 전달한 텍스트로 표시하며, 선택적으로 기존
액션을 함께 둡니다. 이 레시피는 메타데이터를 설명할 뿐이며, 콘텐츠 자체는 애플리케이션에
남습니다.

```rust
Attachment::new(
    "configuration-attachment",
    "session-configuration.json",
    "application/json",
    format!("{} bytes (UTF-8)", configuration.len()),
    palette,
)
.action(inspect_json_button)
```

네이티브 Group의 접근 가능한 이름은 전체 파일 이름입니다. 설명은 파일 이름 아래에 표시되는
것과 같은 `media_type · size_label` 텍스트입니다. 화면에 보이는 파일 이름과 메타데이터
자식에는 별도의 네이티브 역할이나 이름이 없으므로, 각 값은 그룹을 통해 한 번만 노출됩니다.
전달된 액션 Button은 자신의 이름과 역할을 유지합니다. 첨부 프레임은 Tab 스톱, 행 전체
클릭, 선택 상태, 링크 대상, 라이브 알림을 추가하지 않습니다.

세 메타데이터 값은 모두 전달받은 문자열입니다. 단위, 현지화, 메타데이터가 없을 때의 표현은
애플리케이션이 선택합니다. 레시피는 파일 이름을 파싱하거나, 유형을 추론하거나, 파일을
검사하거나, 바이트 수를 서식화하거나, 주장된 크기를 검증하지 않습니다. 0바이트도 그대로
표시할 수 있습니다. 메타데이터 자체가 문서 뷰어나 파일 링크를 제공하지 않으므로 일반
Group을 사용합니다. Item의 범용 제목/설명 행과 달리 Attachment는 명시적인 파일
메타데이터를 갖습니다. Message의 작성된 Comment와 본문과 달리, 작성자나 전달을 주장하지
않고 별도의 콘텐츠 리소스를 식별합니다.

프레임은 크기가 제한된 부모를 채웁니다. 파일 이름과 메타데이터는 잘리지 않고 줄바꿈되며,
프레임은 세로로 늘어납니다. 액션은 텍스트 아래에 놓여 파일 이름과 너비를 다투지 않습니다.
`Styled`로 프레임과 상속되는 텍스트 표현을 사용자 정의합니다. 긴 컬렉션은 애플리케이션의
기존 ScrollArea에 넣으세요. `.action(...)`은 요소 하나를 받으며, 기존 Button이나 사용 가능한
너비에 맞게 컨트롤을 배치한, 애플리케이션이 소유하는 컨테이너를 넣을 수 있습니다. Button은
계속해서 활성화 상태, 포인터/Enter/Space 활성화, 포커스, Tab/Shift+Tab 이동을 소유합니다.
포커스된 액션을 제거할 때의 포커스 정책은 애플리케이션이 소유하며, Attachment에는 새로운
포커스 컨트롤러가 없습니다.

두 모양 모두 Help의 State ownership 패널에서 기존 CodeBlock 위에 Attachment를 사용합니다.
소비자 코드는 현재 설정을 한 번 직렬화하고, 같은 문자열을 코드와 메타데이터에 사용하며,
`session-configuration.json`, `application/json`, 그리고 UTF-8 바이트 수를 표시합니다.
이름이나 메모를 편집하면 표시된 JSON과 함께 이 메타데이터도 바뀝니다. Inspect JSON은 기존
코드 뷰포트로 포커스를 옮기고, 기존 스크롤과 키보드 동작을 사용합니다. 설명 텍스트는 이
콘텐츠가 메모리에 있으며 저장되지 않았음을 밝힙니다. 파일을 만들거나 열지 않으며, 업로드나
다운로드도 일어나지 않습니다. 기존 CodeBlock의 Copy 액션은 독립적으로 유지됩니다.
Attachment는 클립보드 작업, 미리 보기 렌더러, 진행 상태, 전송, 저장 메커니즘을 추가하지
않습니다.
