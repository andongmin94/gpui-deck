[`sidebar.rs`](https://github.com/andongmin94/gpui-design/blob/main/crates/base/examples/recipes/sidebar.rs)는 일반 Button과
유지되는 `TabsState`의 고정 항목 및 선택으로 이름 있는 내비게이션을 조합합니다.

```rust
// Create and retain a state dedicated to this Sidebar, and observe its changes.
let sections = cx.new(|cx| TabsState::new(items, cx));

Sidebar::new("settings-sections", &sections, "Settings sections", palette);
```

루트는 네이티브 Navigation 시맨틱과 전달된 레이블을 노출합니다. 각 항목은 해당 항목의
레이블로 이름 붙은 Button이며, 그 항목의 안정적인 `tab_focus_handle(index)`를 사용합니다.
비활성화된 항목은 비활성화 화면 표현을 유지하며 일반 Tab 이동에서 건너뜁니다. 선택된 항목은
`Button::current(true)`를 설정해 `Button::selected(...)`와 그 시각적 강조와는 별개로
네이티브 `AriaCurrent::Page`를 제공합니다. 항목은 Button 역할을 유지하며, 내비게이션은
탭 선택 메타데이터를 노출하지 않습니다.

| 입력 | 결과 |
| --- | --- |
| Tab / Shift-Tab | 선택된 섹션을 바꾸지 않고 활성화된 항목과 주변 컨트롤 사이를 이동합니다 |
| Enter / Space / 클릭 | `TabsState::select_value`를 통해 활성화한 항목을 선택합니다 |
| 화살표 키 | 선택된 섹션을 바꾸지 않습니다 |

콘텐츠 렌더링과 대상 포커스는 애플리케이션이 소유합니다. 선택된 섹션만 렌더링하고 적절한
이름 있는 Region을 주세요. 비활성 섹션은 컨트롤이나 접근성 노드를 마운트된 채로 남기면 안
됩니다. 입력 엔티티와 폼 값은 애플리케이션에 두어 섹션을 전환해도 보존되게 하세요.
`select_value`를 통한 선택은 포커스를 옮기지 않습니다. Breadcrumb처럼 다른 표면에서
명시적으로 이동할 때도 유지되는 포커스 대상을 선택해야 합니다.

Sidebar에는 새 `TabsState`를 사용하고, TabList, Tab, TabPanel이 사용하는 상태와 분리하세요.
TabList는 자동 포커스-선택 구독을 설치하며, 이 구독은 마운트 해제된 뒤에도 상태에 남습니다.
그 상태를 Sidebar에 재사용하면 포커스 변경이 선택을 바꾸게 되어 명시적 활성화 계약이 깨집니다.
이 제한은 두 화면 표현을 함께 마운트할 때뿐 아니라 서로 전환할 때도 적용됩니다. 예제는 고정된
각 모양마다 별도의 Demo와 상태를 만듭니다.

기본 Sidebar는 10 rem 세로 열입니다. `Styled`로 너비, 간격, 화면 표현을 바꿀 수 있으며,
소비자는 이를 현재 콘텐츠 옆에 두거나 둘을 쌓을 수 있습니다. Settings는 기존 Sheet 안에서
이를 사용합니다. 뷰포트 너비가 640 px 미만이면 Sidebar는 현재 Region 위에서 전체 너비가
됩니다. 이는 레이아웃만 바꾸며, 같은 Button, 선택 항목, 키보드 동작, 포커스 핸들을 유지합니다.
Compact는 계속해서 자체 가로 TabList와 TabPanel 조합을 사용합니다. Breadcrumb의 Session
settings 액션은 어느 모양에서든 Preferences를 명시적으로 선택하고 그 내비게이션 항목에
포커스합니다.

네이티브 제목을 갖는 이름 있는 그룹에는 `.group("Workspace", ["preferences", "help"])`를
사용하세요. 값은 기존 항목을 가리켜야 하며 최대 한 그룹에만 속할 수 있습니다. 그룹에 속하지
않은 항목이 먼저 나타납니다. 그룹화는 표시 순서를 바꾸지만, 항목 ID와 포커스 핸들은 원래
인덱스를 유지합니다.

`CollapsibleState::new(cx).default_open(true)`를 유지하고 관찰하면서
`.collapsible(&sidebar_disclosure)` 또는
`.collapsible_group("Session", ["schedule", "presets"], &session_disclosure)`를 추가하세요.
펼침/비활성화 메타데이터, 키보드 활성화, 활성 상태일 때만 표시되는 콘텐츠, 닫기로 포커스된
항목이 제거될 때의 포커스 복원은 기존 Collapsible이 소유합니다. 펼침 트리거는 마운트된 채로
유지됩니다. 내비게이션을 닫아도 선택된 페이지는 보존되며, 별도의 Region은 계속 애플리케이션이
소유합니다. 카탈로그의 Project 사이드바는 좁은 레이아웃을 포함해 전체 닫기와 그룹 닫기를
보여 줍니다.

`.rail(&rail_state)`는 대신 Sidebar를 shadcn의 `collapsible="icon"`처럼 아이콘 레일로
접습니다. 열린 상태에서는 레이블을 보여 주고, 닫힌 상태에서는 내비게이션을 3.5 rem으로
좁히며 모든 항목을 아이콘만 있는 Button으로 마운트해 둡니다. 이 Button은 같은 접근 가능한 이름,
현재 페이지 메타데이터, 포커스 핸들을 유지하며, 이름을 보여 주는 GPUI 호버 툴팁이 추가됩니다.
레일에서는 그룹 제목과 그룹 펼침이 숨겨지지만 이름 있는 Group은 남습니다. 항목 뒤에 놓이는
`"<label> labels"`라는 이름의 CollapsibleTrigger가 상태를 전환하며 이를 펼침/접힘으로
노출합니다. `.icon(value, || element)`는 항목별 장식용 아이콘을 제공하며, 나머지 항목은 작은
프레임 안에 첫 글자를 표시합니다. 설치된 글꼴에 의존하는 기호 글리프보다 직접 그린 도형을
권장합니다. Sidebar는 `.rail`과 `.collapsible` 중 하나만 사용하며 둘을 함께 쓰지 않습니다.
Settings의 Session sections Sidebar가 레일을 보여 줍니다.

레시피는 라우팅, 내비게이션 기록, 별도의 선택 모델을 추가하지 않습니다. Settings는 기존
Sheet의 스크롤되는 본문과 모달 포커스 가두기를 사용합니다.
