値が一意な、順序付きの `SearchItem::new(value, label)` エントリから
`CommandState::new(items, window, cx)` を作成します。任意の `.keywords` は
検索用のエイリアスを追加し、`.disabled(true)` はアクションを利用不可にします。結果の描画のために State を
observe し、実行の処理をアプリケーションで行うには `CommandEvent::Action(value)` を購読します。

`Command::new(id, &state)` は `CommandInput::new(id, &state)` と
`CommandList::new(id, &state)` をホストします。クエリとリストにアクセシブルなラベルを付け、
`visible_indices()` の各要素について、その順序で `CommandOption::new(&state, index)` を描画します。
`.group(label)` を持つ項目では、一致するオプションを名前付きの `CommandGroup` パーツで囲みます。
`visible_groups()` と `visible_group_indices(Some(label))` が絞り込まれた
コレクションを公開します。各グループはソース内で連続させてください。空のグループは表示されなくなります。
グループの見出しにはフォーカスストップがなく、キーボードナビゲーションに影響しません。ラベルには `items()` を、
アプリケーションが管理するアクティブ行のスタイルには `highlighted_index()` を読み取ります。リストは
既存の GPUI の ScrollHandle を使用します。アクティブな結果がスクロールして表示されるよう、高さまたは最大の高さを与えてください。
一致する項目がない場合は、アプリケーションが管理する空のメッセージを描画します。

既存の InputState がクエリの信頼できる情報源であり、`input()` を通じて公開されます。
`set_query(text, window, cx)` はそれをプログラムから更新します。空白で区切られた各クエリ語の文字は、
大文字小文字を無視して、項目の value、label、keywords の中に順番どおりに現れなければならないため、`pnt` は "Show pointer" を見つけます。結果は、
単語の先頭での一致を他の部分文字列より上位に、それらをより緩い順序どおりの文字より上位にランク付けし、
クエリ語ごとに合計します。グループは連続したままで、最良の結果の順に並び、
スコアが同じ場合や空のクエリではソース順が保たれます。
マッチングは表示のために無効な結果も含みます。クエリが変わると
最初の有効な結果がハイライトされ、空の結果やすべて無効な結果にはアクティブな
コマンドがありません。`set_items(items, window, cx)` はネイティブのクエリとフォーカスを保ったままコレクションを置き換え、
一致する有効なハイライトを value で保持するか、最初の有効な結果を選びます。取得とリクエストの
順序はアプリケーションが管理します。ネットワークコントローラーは提供されません。

| 入力 | 動作 |
| --- | --- |
| Up / Down | 一致する有効な結果の間を移動し、端では反対側へ循環します |
| Enter | ハイライトされた有効な結果を 1 回実行します |
| ポインターのホバー / クリック | 有効な結果をハイライトする / その結果を実行します |
| Space、Home、End、Left、Right | 通常のクエリ編集のままです |
| Tab / Shift-Tab | 通常のコンテナのフォーカス移動に従います。結果の行は Tab ストップではありません |
| Escape | 周囲のサーフェスが利用できる状態のままです |

ネイティブのフォーカスはクエリに留まります。IME がマークされた入力中のテキストを持っている間は、
コマンドのナビゲーションと実行は、その操作を input に任せます。自動化された
マークされたテキストのチェックは、デスクトップでの韓国語/CJK の IME の検証の代わりにはなりません。

ネイティブツリーは、名前付きのテキスト input、リストボックス、選択済み/無効なオプションを公開します。
固定された GPUI の active-descendant API はフォーカスされた祖先を必要とします。兄弟の
クエリ/リストはその関係を正しく出力できないため、この実装は
その関係も、スクリーンリーダーでの検証の完了も主張しません。

Command 自体はポップアップのライフサイクルを持ちません。コマンドパレットを作るには、
既存の Dialog の内側に配置し、DialogState の初期フォーカスを
`focus_handle()` に設定します。サンプルは、別の Dialog を開く可能性のあるアクションを実行する前にその Dialog を閉じ、
メニューのトリガーを復帰先として保ちます。
パレットを開くときのクエリのクリアは、アプリケーションのコードで行います。

SearchItem と検索の実装は、編集可能な
[Combobox](./combobox.mdx) でも使用されます。Combobox は独自の確定値と
ポップアップのライフサイクルを提供し、Command はアクションのリストのままです。
