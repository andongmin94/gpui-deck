title: Textarea
description: "同じエンジンによる複数行の編集、保持されるテキスト、折り返し、通常のフォームの Tab 移動に対応します。"
---

`Textarea::new(&state)` は、既存の複数行編集エンジンを描画します。
`TextareaState::new(window, cx)` を一度だけ構築し、固定の行数には `.rows(3)` を、
範囲を限定した自動拡張には `.auto_grow(min, max)` を使用します。State は
プレースホルダー/デフォルトのテキストとソフトラップもサポートし、選択、元に戻す操作、スクロール、クリップボード、
ネイティブのテキスト入力インターフェースは、同じ保持されたエンティティの中に留まります。

`Role::MultilineTextInput` とアクセシブルなラベルを持つ `InputAccessibility` を指定します。
アプリケーションが管理するフレームのために、レンダラーを `InputBase` で包み、
フレームには `.role(None::<Role>)` と `.semantic_owner::<Textarea>(state.entity_id())` を設定して、
テキストエンティティがネイティブのセマンティクスとフォーカスの唯一の所有者になるようにします。サンプルは、
1 行のフィールドと複数行のノートの両方に、同じアプリケーションのパレットを使用しています。

Enter はデフォルトで改行を挿入します。Tab と Shift-Tab は、行数指定と自動拡張のどちらの textarea でも
通常のフォームナビゲーションに従い、コードエディターのインデントは
別の機能です。`set_disabled(bool, cx)` は編集と通常の Tab の進入を防ぎます。
フォーカス中に無効化されたフィールドは、Tab で離れられるようバインディングを保ちます。再び有効にすると
進入が復元されます。`set_readonly(bool, cx)` はフォーカスと選択を保ちつつ編集を防ぎます。
プログラムによる `set_value` は、アプリケーションの更新のために引き続き利用できます。
ネイティブの input ノードは、利用可能な編集アクションとともに、
読み取り専用の状態を明示的に公開します。

State は、折りたたみ可能なセクション、タブパネル、Dialog の描画経路の外に保持して、
そのサーフェスを閉じてもテキストが保たれるようにしてください。サンプルは、設定ダイアログを閉じて開き直しても
Session notes を保持します。
