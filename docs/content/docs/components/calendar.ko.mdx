`CalendarState`는 `CalendarSelection`, 포커스된 날짜, 보이는 월을 유지합니다.
`NaiveDate`는 Chrono에서 다시 내보낸 것이며, 두 번째 날짜 모델이나 시간대 변환은
도입하지 않습니다. 상태는 한 번만 생성합니다.

```rust
let calendar = cx.new(|cx| {
    let initial = NaiveDate::from_ymd_opt(2026, 11, 9).unwrap();
    CalendarState::new(initial, cx)
        .bounds(
            NaiveDate::from_ymd_opt(2026, 1, 1).unwrap(),
            NaiveDate::from_ymd_opt(2027, 12, 31).unwrap(),
        )
        .default_selection(CalendarSelection::Single(Some(initial)))
});
```

`default_selection`이 없으면 선택은 `CalendarSelection::Single(None)`으로 시작합니다.
기본 범위는 1–9999년이며, `bounds`는 마운트 전에 선택 가능한 포함 범위를 좁힙니다.
그리드는 `days()`를 통해 완전한 6주를 노출하며, 기본적으로 월요일부터 시작합니다.
인접한 달의 날짜도 계속 보이고, 설정된 범위를 벗어난 날짜는 비활성화됩니다.

마운트 전에 `.week_starts_on(Weekday::Sun)`을 쓰면 그리드와 Home/End 경계가 바뀝니다.
헤더 순서를 맞추려면 `weekdays()`를 사용합니다. `Weekday`는 `NaiveDate`와 함께
다시 내보내집니다. `.disabled_dates(|date| ...)`는 주말이나 예약된 날짜 같은
애플리케이션 규칙을 제공합니다. 이 규칙은 기존 단일/다중 값을 걸러 내고, 사용할 수 없는
끝점을 가진 범위는 지웁니다. 기본값과 프로그래밍 방식 설정자는 사용할 수 없는
날짜/끝점을 거부합니다. 범위 내부에는 사용할 수 없는 날이 포함될 수 있습니다.
조건자의 결과는 상태가 살아 있는 동안 일정하게 유지해야 합니다.

`Calendar::new(id, &calendar)`를 접근 가능한 월/연도 레이블과 함께 렌더링합니다.
7칸짜리 요일 헤더 하나와 날짜 행 여섯 개에는 식별자가 있는 일반
`div().id(...).role(Role::Row)` 컨테이너를 사용합니다. 요일 제목은 0부터 시작하는
열 인덱스와 함께 `Role::ColumnHeader`를 사용합니다. 각 `CalendarDay::new(&calendar, date)`는
Button의 활성화/포커스 동작을 조합하고, 네이티브 GridCell 역할, 선택 상태,
비활성화 상태, 행/열 인덱스를 제공합니다. 그리드는 요일 헤더를 포함해 7개 행을
선언합니다. `days()`가 반환하는 각 날짜를 순서대로 정확히 한 번씩 렌더링합니다.
각 날짜의 자식은 비대화형으로 유지합니다.

그리드 기하, 요일 이름, 현지화된 전체 날짜 레이블, 선택된 날짜 스타일, 월 이동 버튼은
애플리케이션이 소유합니다. `CalendarDay`의 기본 접근성 레이블은 ISO 날짜이며,
`.accessibility_label(...)`을 지원하고, 일반 GPUI 스타일과 선택/비활성화 상태용
Button의 `.styles(...)`를 받습니다. 완전한 조합은 네이티브 예제의
`Demo::calendar_content`를 참고하십시오.

| 입력 | 결과 |
| --- | --- |
| Tab / Shift+Tab | 유지되는 하나의 날짜 스톱으로 들어가거나 그리드를 떠납니다 |
| Left / Right | 물리적 셀 하나만큼 포커스를 옮기며, RTL에서는 시간 순서 방향이 반대가 됩니다 |
| Up / Down | 한 주만큼 포커스를 옮깁니다 |
| Home / End | 현재 주의 설정된 첫 번째 / 마지막 날로 이동합니다 |
| Page Up / Page Down | 한 달만큼 이동하며, 월말 날짜는 고정됩니다 |
| Shift+Page Up / Shift+Page Down | 한 해만큼 이동합니다 |
| Enter / Space / click | 활성화된 날짜를 확정합니다. 값이 바뀐 경우에만 Change를 내보냅니다 |

키보드 이동은 월을 넘나들며 선택 가능한 범위에서 멈추고, 확정된 값은 바꾸지 않습니다.
새로 포커스를 받은 날짜는 네이티브 노출을 요청하며, 이를 감싸는 ScrollArea가
처리할 수 있습니다. 월 버튼은 `previous_month` 또는 `next_month`를 호출하고,
비활성화 상태에는 `can_previous_month`/`can_next_month`를 사용합니다.
이 메서드들은 외부 내비게이션 버튼의 포커스를 유지합니다. 포커스를 명시적으로
캘린더 안으로 옮길 때는 `focus_handle()`을 읽습니다. 그리드 슬롯은 보이는 월이
바뀌면 달라질 수 있으므로, 이 핸들을 고정된 날짜 식별자로 캐시하지 마십시오.

범위 안의 사용할 수 없는 날짜는 탐색을 위해 키보드 포커스를 받을 수 있지만
포인터, Enter, Space로 활성화할 수는 없습니다. 모든 날짜를 사용할 수 없는 캘린더도
그리드 Tab 스톱 하나를 유지합니다. Calendar 전체를 비활성화하면 일반 진입과
내비게이션이 제거됩니다. 범위를 벗어난 셀은 포커스 이동에 포함되지 않습니다.

Calendar는 `DirectionProvider`를 상속하거나 `.direction(Direction::Rtl)`을 받습니다.
애플리케이션은 요일/날짜 행에 같은 `Direction::row`를 적용하고 요일 헤더의 열 인덱스를
뒤집어야 합니다. CalendarDay는 감싸는 Calendar로부터 물리적 열과 가로 키보드 방향을
계산합니다. 레이블과 텍스트 서식은 애플리케이션이 소유하며, Selection 카탈로그가
이 레이아웃을 보여 줍니다.

`CalendarSelection`은 `Multiple(Vec<NaiveDate>)`와
`Range { start: Option<NaiveDate>, end: Option<NaiveDate> }`도 지원합니다. 빈 범위는
`.default_selection(CalendarSelection::Range { start: None, end: None })`으로 설정합니다.
첫 번째 활성화는 시작을 고르고, 두 번째 활성화는 역순이나 같은 날 선택을 포함해
순서가 정렬된 포함 끝점을 완성합니다. 완성된 범위를 다시 활성화하면 새 부분 범위가
시작됩니다. 다중 선택은 날짜를 토글하며, 중복 없이 오름차순으로 저장됩니다.
`is_selected(date)`는 범위 안의 모든 선택된 날짜를 포함합니다.

`selection()`은 전체 값을 반환하고, `selection().first_date()`는 요약 표시에 쓸 수
있습니다. `set_selection(selection, window, cx)`는 사용자 이벤트 없이 모드와 값을
바꿉니다. 범위를 벗어난 날짜, 뒤집힌 범위, 시작 없는 끝은 거부합니다. 비어 있지 않은
값은 보이는 월과 커서도 갱신하며, 선택을 지워도 내비게이션은 유지됩니다.
`CalendarEvent::Change(selection)`는 사용자 변경을 보고합니다. `set_disabled`는
사용자 내비게이션/선택과 일반 Tab 진입을 막습니다.

캘린더는 그레고리력을 유지합니다. 비그레고리력 연산, 시계, 시간대 변환은 제공하지
않습니다. Selection 카탈로그는 일요일 시작, 주말 비활성화 범위/다중 날짜, RTL을
보여 주며, 세션 예제는 월요일 시작의 단일 녹화 날짜를 유지합니다.
