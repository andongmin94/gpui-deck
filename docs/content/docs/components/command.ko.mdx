고유한 값을 가진 순서 있는 `SearchItem::new(value, label)` 항목으로
`CommandState::new(items, window, cx)`를 생성합니다. 선택적인 `.keywords`는
검색 별칭을 추가하고, `.disabled(true)`는 액션을 사용할 수 없게 합니다. 결과를
렌더링하려면 상태를 관찰하고, 애플리케이션에서 실행을 처리하려면
`CommandEvent::Action(value)`를 구독합니다.

`Command::new(id, &state)`는 `CommandInput::new(id, &state)`와
`CommandList::new(id, &state)`를 담습니다. 쿼리와 목록에 접근 가능한 레이블을 지정하고,
`visible_indices()`에 대해 그 순서대로 `CommandOption::new(&state, index)`를 렌더링합니다.
`.group(label)` 항목은 일치하는 옵션을 이름 있는 `CommandGroup` 부품으로 감쌉니다.
`visible_groups()`와 `visible_group_indices(Some(label))`가 필터링된 컬렉션을
노출합니다. 각 그룹은 원본에서 연속되게 두며, 빈 그룹은 사라집니다.
그룹 제목에는 포커스 스톱이 없으며 키보드 내비게이션에 영향을 주지 않습니다. 레이블은
`items()`에서, 애플리케이션이 소유하는 활성 행 스타일에는 `highlighted_index()`를
읽습니다. 목록은 기존 GPUI ScrollHandle을 사용하므로, 활성 결과가 보이도록 스크롤될 수
있게 높이나 최대 높이를 지정합니다. 일치하는 항목이 없으면 애플리케이션이 소유하는
빈 상태 메시지를 렌더링합니다.

쿼리의 단일 정보원은 기존 InputState이며, `input()`으로 노출됩니다.
`set_query(text, window, cx)`는 이를 프로그래밍 방식으로 갱신합니다. 공백으로 구분된
각 쿼리 단어의 글자는 대소문자를 무시하고 항목의 값, 레이블, 키워드 안에 순서대로
나타나야 하므로, `pnt`는 "Show pointer"를 찾습니다. 결과 순위는 단어 시작에서의 일치를
다른 부분 문자열보다, 부분 문자열을 느슨한 순서 일치보다 높게 매기며, 단어별 점수를
합산합니다. 그룹은 연속된 상태로 최고 결과 순으로 정렬되며, 점수가 같거나 쿼리가
비어 있으면 원본 순서를 유지합니다.
일치에는 표시용으로 비활성화된 결과도 포함됩니다. 쿼리가
바뀌면 첫 번째 활성화된 결과가 강조되며, 결과가 없거나 모두 비활성화되어 있으면 활성
명령이 없습니다. `set_items(items, window, cx)`는 네이티브 쿼리와 포커스를 유지한 채
컬렉션을 교체합니다. 값 기준으로 일치하는 활성화된 강조를 유지하거나 첫 번째 활성화된
결과를 고릅니다. 가져오기와 요청 순서는 애플리케이션이 소유합니다.
네트워크 컨트롤러는 제공하지 않습니다.

| 입력 | 동작 |
| --- | --- |
| Up / Down | 일치하는 활성화된 결과 사이를 이동하며, 양 끝에서 순환합니다 |
| Enter | 강조된 활성화된 결과를 한 번 실행합니다 |
| Pointer hover / click | 활성화된 결과를 강조합니다 / 해당 결과를 실행합니다 |
| Space, Home, End, Left, Right | 일반 쿼리 편집으로 유지됩니다 |
| Tab / Shift-Tab | 일반 컨테이너 포커스 이동을 따릅니다. 결과 행은 Tab 스톱이 아닙니다 |
| Escape | 주변 화면에서 사용할 수 있도록 남겨 둡니다 |

네이티브 포커스는 쿼리에 머뭅니다. IME에 조합 중인 텍스트가 있는 동안에는 명령
내비게이션과 실행을 입력에 맡깁니다. 자동화된 조합 텍스트 검사가 데스크톱
한국어/CJK IME 검증을 대신하지는 않습니다.

네이티브 트리는 이름 있는 텍스트 입력, listbox, 선택/비활성화 옵션을 노출합니다.
고정된 GPUI active-descendant API는 포커스된 조상을 요구합니다. 형제 관계인
쿼리/목록은 이 관계를 사실대로 내보낼 수 없으므로, 이 구현은 그런 관계나 완료된
스크린리더 검증을 주장하지 않습니다.

Command 자체는 팝업 수명 주기를 소유하지 않습니다. 명령 팔레트를 만들려면 기존
Dialog 안에 두고 DialogState의 초기 포커스를 `focus_handle()`로 설정합니다. 예제는
다른 Dialog를 열 수 있는 액션을 실행하기 전에 이 대화 상자를 닫아, 메뉴 트리거를
복귀 대상으로 유지합니다. 팔레트를 열 때 쿼리를 지우는 것은 애플리케이션 코드가 합니다.

SearchItem과 검색 구현은 편집 가능한
[Combobox](./combobox.mdx)에서도 사용됩니다. Combobox는 자체 확정 값과
팝업 수명 주기를 제공하고, Command는 액션 목록으로 남습니다.
