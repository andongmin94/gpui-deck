`MessageScrollerState::new(cx)` は、既存の ScrollHandle に加えて、前のフレームの
安定したメッセージキーと閲覧位置を管理します。`MessageScroller::new(id, &state, cx)` に高さの上限を与え、
各メッセージを `.item(stable_id, content)` で追加します。ID は会話内で一意でなければならず、
各メッセージの子コントロールのスコープにもなり、並べ替えを通じてそれらの同一性を保ちます。
別の会話に切り替えるときは新しい State を作成します。既存の ScrollArea が
ホイール/トラックパッドによるスクロール、クリッピング、スクロールバーの操作を担当します。

最初のフレームは最下部から始まります。閲覧者が最下部にいる間は、メッセージの追加、
ストリーミングによる編集、リサイズに追従し続けます。閲覧者が離れると、履歴が先頭に追加されたり
以前の項目の高さが変わったりしても、最初に見えているメッセージはピクセル位置を保ちます。補正は同じレイアウトフレーム内で行われます。
アンカーを削除した場合は、通常のネイティブのオフセットの制限が働きます。離れている間の
追加は `unread_count` を増やし、`jump_to_latest` は、呼び出し元のコントロールから
フォーカスを移さずに追従を再開します。最下部に戻ると未読がクリアされ、
同じフレーム内でリサイズやコンテンツの削除によって最下部が現れた場合も同様です。
仮想化やチャットの通信は含まれません。
