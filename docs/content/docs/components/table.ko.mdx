Table은 열을 한 번 정의하고 헤더, 본문, 푸터에 적용합니다. 각 행은 열마다 정확히
하나의 셀을 제공해야 합니다. 안정적인 트랙에는 고정 너비를 사용하고, 남은 너비를
나누려면 양수인 가변 가중치를 사용합니다.

```rust
Table::new(
    "sessions",
    [TableColumn::fixed(px(180.)), TableColumn::flex(1.)],
)
.accessibility_label("Sessions")
.w_full()
.header(
    TableRow::new("sessions-header")
        .cell(TableCell::new("session-heading").p_2().child("Session"))
        .cell(TableCell::new("date-heading").p_2().child("Date")),
)
.row(
    TableRow::new("session-1")
        .cell(TableCell::new("session-1-name").row_header(true).p_2().child("Workshop"))
        .cell(TableCell::new("session-1-date").p_2().child("2026-11-09")),
)
.caption(TableCaption::new("sessions-caption").child("Scheduled sessions"))
```

`header`와 `footer`는 각각 행 하나를 받습니다. 본문 행은 `row` 또는 `rows`로
추가하며, `TableRow::cells`도 이터레이터를 받습니다. 빈 본문도 유효하므로
애플리케이션은 표 옆에 빈 상태 안내를 렌더링할 수 있습니다.

모든 부분은 `Styled`를 구현합니다. 셀과 캡션은 임의의 자식을 받으므로,
애플리케이션은 기존 Button이나 Checkbox를 셀에 넣을 수 있습니다. 구조적인 표 부분은
Tab 스톱을 추가하지 않으며 그런 컨트롤의 활성화를 가로채지 않습니다. 행의 가로
레이아웃은 Table이 소유합니다. 행에 가로 패딩, 마진, 간격을 추가하지 말고 셀
안에서 간격을 적용합니다. 셀 스타일은 내부 콘텐츠 표면에 적용되므로, 헤더와 본문의
패딩이 달라도 공유되는 바깥 열 너비가 유지됩니다.

| 부분 | 네이티브 시맨틱 |
| --- | --- |
| Table | Table, 행 개수, 열 개수, 명시적인 접근 가능한 레이블 |
| 헤더/본문/푸터 | RowGroup |
| 행 | Row와 0부터 시작하는 인덱스 |
| 헤더 셀 | 행/열 인덱스가 있는 ColumnHeader |
| 일반 셀 | 행/열 인덱스가 있는 Cell |
| `row_header(true)`인 셀 | 열 헤더 행에 속하지 않는 한 RowHeader |
| 캡션 | 포커스 액션이 없는 Caption |

인덱스에는 헤더와 푸터가 포함됩니다. 보이는 캡션이 표의 이름을 자동으로 지정하지는
않으므로 `accessibility_label`을 별도로 제공합니다. 보이는 콘텐츠가 이름을 제공하지
않으면 셀에도 명시적인 접근 가능한 레이블을 지정할 수 있습니다.

이것은 셀 내비게이션이나 데이터 컨트롤러가 없는 일반 표입니다. 행/열 병합, 자동
내재 열 크기 지정, 정렬, 필터링, 페이지 나누기, 선택 관리, 가상화는 제공하지
않습니다. `TableRow::selected`와 `TableCell::sort_direction`은 애플리케이션이
소유하는 선택과 정렬을 네이티브 메타데이터로 반영할 뿐, 데이터 작업을 수행하지
않습니다. 실제 애플리케이션에서 데이터 작업이 필요하면 이 구조 위에 조합합니다.

복사해서 쓸 수 있는 [DataTable 레시피](../recipes/data-table.mdx)는 텍스트 필터링,
단일 열 정렬, 페이지 나누기, 페이지/행 체크박스 선택, 열 표시 여부, 빈 상태 복구,
안정적인 ID 기반 행 액션을 추가합니다. 네이티브 예제는 이를 사용해 녹화 프리셋을
탐색하고 적용합니다. 쿼리와 페이지 상태는 Table 바깥의 애플리케이션에 속합니다.
