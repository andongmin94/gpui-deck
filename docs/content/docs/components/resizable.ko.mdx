Resizable은 경계가 있는 프레임을 둘 이상의 연속 배치된 패널로 나누고, 패널 사이를
포커스 가능한 구분선으로 분리합니다. 상태는 패널 크기, 각 패널의 제약 조건,
구분선마다 하나씩의 포커스 핸들을 소유합니다.

```rust
let split = cx.new(|cx| {
    ResizableState::new(
        Axis::Horizontal,
        [
            ResizablePanel::new(0.25).limits(0.15..=0.4).collapsible(0.),
            ResizablePanel::new(0.5).limits(0.3..=1.),
            ResizablePanel::new(0.25).limits(0.15..=0.4),
        ],
        cx,
    )
});

Resizable::new("workspace", &split)
    .size_full()
    .panel(sidebar)
    .panel(editor)
    .panel(inspector)
    .handle(|index, handle| {
        handle
            .accessibility_label(["Sidebar width", "Editor width"][index])
            .w(px(6.))
            .bg(divider_color)
    })
```

구성한 패널마다 순서대로 `panel`을 하나씩 제공합니다. `handle`은 모든 구분선을
인덱스로부터 만들며, 이 인덱스는 구분선 앞에 있는 패널의 인덱스입니다.
`Axis::Horizontal`은 패널을 왼쪽에서 오른쪽으로 배치하고 핸들의 너비를 사용합니다.
`Axis::Vertical`은 위에서 아래로 배치하고 핸들의 높이를 사용합니다. 프레임의
크기에 경계를 두고 핸들에 실제 두께를 지정합니다. 크기는 구분선 두께를 뺀 사용
가능한 공간에 대한 비율이며, 합은 1이고, 부모 크기가 바뀌어도 비율을 유지합니다.
프레임 패딩은 지원하지만 내부 레이아웃에는 간격이 없습니다.

`ResizablePanel::new(default)`는 0과 1 사이에서 자유롭게 시작합니다. `limits`는
펼쳐진 크기의 범위를 제한하고, `collapsible(size)`는 더 작은 접힌 크기를
허용합니다. 기본값이 패널의 제약 조건을 어기거나 합이 1이 아니면 상태 생성 시
panic이 발생합니다. `pixel_limits(min..=max)`는 그룹이 측정된 뒤에 적용되는
논리 픽셀 범위를 추가하며, 비율 범위와 픽셀 범위 중 더 엄격한 쪽이 우선합니다.
측정된 공간이 바뀌어 레이아웃이 새 범위를 벗어나면 가까운 패널부터 한 번 다시
맞추고 Change를 발생시킵니다. 여전히 유효한 레이아웃은 비율을 유지합니다. 공간이
모든 픽셀 제한을 만족할 수 없으면, 만족할 수 있을 때까지 그룹은 비율 제한만
사용합니다. 구분선 값과 Home/End는 측정된 범위를 반영합니다.

구분선을 움직이면 한쪽 패널이 커지고 반대쪽 패널들은 가까운 것부터 줄어듭니다.
따라서 최솟값에 도달한 패널은 이동을 다음 패널로 넘깁니다. 어떤 패널도 흡수할 수
없는 이동이면 구분선은 제자리에 남습니다. 접을 수 있는 패널의 최솟값과 접힌 크기의
중간 지점을 넘어 드래그하면 패널이 닫히며, 다시 그 지점을 넘어 되돌리면 최솟값으로
다시 열립니다.

| 입력 | 결과 |
| --- | --- |
| 구분선 드래그 | 실제로 누른 위치부터 크기를 조절하며, 제약 조건 안에서 연쇄 적용 |
| 가로 그룹에서 Left / Right | 구분선 앞 패널을 2퍼센트포인트 줄이기 / 늘리기 |
| 세로 그룹에서 Up / Down | 구분선 앞 패널을 2퍼센트포인트 줄이기 / 늘리기 |
| 접힌 패널 쪽 화살표 | 최솟값으로 다시 열기 |
| 최솟값인 접을 수 있는 패널 반대쪽 화살표 | 접기 |
| Home / End | 구분선 앞 패널을 허용되는 가장 작은 / 가장 큰 크기로 설정 |
| Enter | 구분선 앞의 접을 수 있는 패널을 접거나 마지막 크기로 복원 |
| Tab / Shift+Tab | 일반 문서 순서로 구분선과 패널 컨트롤을 순회 |

Home, End, Enter는
[APG 창 스플리터 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/)을
따릅니다. 크기 조절 키 컨텍스트는 구분선만 소유합니다. 패널 안의 텍스트 편집,
선택, 스크롤은 각자의 동작을 유지합니다. 포인터 드래그는 GPUI의 드래그 수명 주기를
사용하고 자신을 소유한 상태와 구분선을 식별하므로, 독립적이거나 중첩된 그룹은
다른 구분선의 드래그에 반응하지 않습니다.

각 구분선은 네이티브 Splitter 역할을 가지며, 그 숫자 값, 제한, 단계는 구분선 앞
패널을 퍼센트로 나타냅니다. 네이티브 방향은 구분선 자체를 나타냅니다. 각 구분선에
조절하는 패널을 가리키는 레이블을 지정하고, 손잡이 자식은 상호작용하지 않게
유지합니다. 모든 스타일은 애플리케이션이 제공합니다.

크기 0으로 접힌 패널은 콘텐츠를 언마운트하므로 포커스 스톱이나 접근성 노드를
제공하지 않습니다. 포커스가 그 안에 있었다면 인접한 구분선으로 옮겨 갑니다(크기
조절이 비활성화된 동안에는 그룹 자체로 옮겨 갑니다). 아이콘 레일처럼 0이 아닌 접힌
크기는 콘텐츠를 마운트된 상태로 유지합니다.

화면 표현을 갱신하려면 상태를 관찰합니다. `sizes()`, `panel_count()`,
`is_collapsed(index)`, `axis()`, `handle_focus(index)`, `is_disabled()`가
계약을 노출합니다. `set_sizes`는 레이아웃 전체를 교체하고 잘못된 레이아웃이면
panic이 발생하며, 이후 측정된 픽셀 제한에 맞춥니다. 레이아웃을 저장하려면
`ResizableEvent::Change`에서 받은 `sizes()`를 애플리케이션 저장소에 보관하고
다음 실행 시 `set_sizes`에 전달합니다.
`collapse(index)`와 `expand(index)`는 접을 수 있는 패널에 작동하며, 이웃 패널이
변화를 흡수할 수 없으면 아무것도 하지 않습니다. 레이아웃이 바뀔 때마다
프로그래밍 방식의 갱신을 포함해 `ResizableEvent::Change(sizes)`가 한 번
발생합니다. `set_disabled`는 포인터, 키보드, 접근성을 통한 크기 조절과 일반적인
Tab 진입을 막습니다. 포커스된 구분선은 Tab으로 떠날 수 있도록 바인딩을 유지합니다.

Schedule 예제는 공유 메모를 접을 수 있는 첫 번째 패널에 두고, 계획 표를 두 번째
패널의 양방향 ScrollArea에 둡니다. 두 번째 패널은 최소 96 px를 유지합니다.
애플리케이션이 상태를 유지하므로 탭을 닫거나 전환해도 텍스트와 크기가
보존됩니다. 라이브러리는 파일을 쓰지 않으며, 저장 위치는 애플리케이션이 결정합니다.
