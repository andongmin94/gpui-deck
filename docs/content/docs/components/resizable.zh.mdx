Resizable 将一个有界框架划分为两个或更多连续布局的
面板，面板之间由可聚焦的分隔条隔开。其状态持有面板尺寸、每个
面板的约束，以及每个分隔条各一个焦点句柄：

```rust
let split = cx.new(|cx| {
    ResizableState::new(
        Axis::Horizontal,
        [
            ResizablePanel::new(0.25).limits(0.15..=0.4).collapsible(0.),
            ResizablePanel::new(0.5).limits(0.3..=1.),
            ResizablePanel::new(0.25).limits(0.15..=0.4),
        ],
        cx,
    )
});

Resizable::new("workspace", &split)
    .size_full()
    .panel(sidebar)
    .panel(editor)
    .panel(inspector)
    .handle(|index, handle| {
        handle
            .accessibility_label(["Sidebar width", "Editor width"][index])
            .w(px(6.))
            .bg(divider_color)
    })
```

按顺序为每个已配置的面板提供一个 `panel`。`handle` 根据索引构建每个
分隔条，该索引即其前一个面板的索引。
`Axis::Horizontal` 将面板从左到右排列，并使用手柄的宽度；
`Axis::Vertical` 将它们从上到下排列，并使用其高度。请限定框架的
尺寸，并为手柄设置实际的厚度。尺寸是扣除分隔条厚度后可用
空间的比例，总和为 1，并在父元素调整大小时保持
比例不变。框架支持内边距；内部布局没有间隙。

`ResizablePanel::new(default)` 起初在零和一之间自由取值。`limits`
限定展开时的尺寸，`collapsible(size)` 允许一个更小的折叠
尺寸。当默认值违反某个面板的约束
或总和不为 1 时，构造状态会 panic。`pixel_limits(min..=max)` 添加以逻辑像素为单位的边界，
在该组被测量后生效；比例边界和像素边界中更严格的那个
优先。当测得的空间发生变化时，违反新边界的布局
会被重新拟合一次，由近及远，并触发 Change；仍然有效的布局会保持其
比例。如果空间无法满足所有像素限制，该组只使用
比例限制，直到能够满足为止。分隔条的值以及 Home/End 反映
测得的边界。

移动分隔条会使一侧的面板增大，并使另一侧的面板
由近及远地缩小，因此已达最小值的面板会将该移动传递给下一个
面板。没有任何面板能够吸收的移动会让分隔条保持原位。拖动超过
可折叠面板最小尺寸与折叠尺寸之间的中点时，它会吸附为
关闭；拖回越过该点则会以其最小尺寸重新打开。

| 输入 | 结果 |
| --- | --- |
| 拖动分隔条 | 从实际按下的位置开始调整，在约束范围内级联 |
| 水平组中的左 / 右 | 将分隔条前的面板缩小 / 增大两个百分点 |
| 垂直组中的上 / 下 | 将分隔条前的面板缩小 / 增大两个百分点 |
| 朝向已折叠面板的方向键 | 以其最小尺寸重新打开 |
| 背向处于最小尺寸的可折叠面板的方向键 | 将其折叠 |
| Home / End | 使分隔条前的面板取其允许的最小 / 最大尺寸 |
| Enter | 折叠分隔条前的可折叠面板，或恢复其上一次的尺寸 |
| Tab / Shift+Tab | 按普通的文档顺序遍历分隔条和面板控件 |

Home、End 和 Enter 遵循
[APG 窗口分隔条模式](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/)。
只有分隔条拥有调整大小的按键上下文。面板内的文本编辑、选择和滚动
保留各自的行为。指针拖动使用 GPUI 的拖动
生命周期，并标识其所属的状态和分隔条，因此独立或嵌套的
组不会响应另一个分隔条的拖动。

每个分隔条都有原生的 Splitter 角色，其数值、限制和步长
描述的是它前面的面板，以百分比表示。原生方向描述的是
分隔线。请为每个分隔条提供一个标签，说明它所调整的面板，并保持其
抓握部分的子元素为非交互式。所有样式由应用提供。

折叠为零尺寸的面板会卸载其内容，因此它不提供焦点
停靠点或无障碍节点。如果焦点原本位于其中，它会移到相邻的
分隔条（在调整大小被禁用时则移到组本身）。非零的折叠
尺寸（例如图标栏）会保持其内容处于挂载状态。

观察该状态以更新呈现。`sizes()`、`panel_count()`、
`is_collapsed(index)`、`axis()`、`handle_focus(index)` 和 `is_disabled()`
暴露其约定。`set_sizes` 会替换整个布局，遇到
无效布局时会 panic，然后将其拟合到测得的像素限制。要持久化布局，
请在应用存储中保存来自 `ResizableEvent::Change` 的 `sizes()`，并在下次启动时
将其传给 `set_sizes`。
`collapse(index)` 和 `expand(index)` 作用于可折叠面板，当
相邻面板无法吸收该变化时不做任何事。每次布局变化都会触发一次
`ResizableEvent::Change(sizes)`，包括程序化的更新。`set_disabled`
会阻止指针、键盘和无障碍的调整大小以及正常的 Tab 进入；获得焦点的
分隔条会保留其绑定，以便 Tab 可以离开。

Schedule 示例将共享的备注放在可折叠的第一个面板中，将
计划表放在第二个面板的双轴 ScrollArea 中，该面板至少保持 96 px。
关闭或切换标签页
会保留文本和尺寸，因为应用保留了它们的状态。库
不会写入任何文件；存储位置由应用决定。
