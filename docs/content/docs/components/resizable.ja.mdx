Resizable は、範囲を限定したフレームを、フォーカス可能な区切りで分けられた、連続してレイアウトされる
2 つ以上のパネルに分割します。その State は、パネルのサイズ、各
パネルの制約、区切りごとのフォーカスハンドルを管理します。

```rust
let split = cx.new(|cx| {
    ResizableState::new(
        Axis::Horizontal,
        [
            ResizablePanel::new(0.25).limits(0.15..=0.4).collapsible(0.),
            ResizablePanel::new(0.5).limits(0.3..=1.),
            ResizablePanel::new(0.25).limits(0.15..=0.4),
        ],
        cx,
    )
});

Resizable::new("workspace", &split)
    .size_full()
    .panel(sidebar)
    .panel(editor)
    .panel(inspector)
    .handle(|index, handle| {
        handle
            .accessibility_label(["Sidebar width", "Editor width"][index])
            .w(px(6.))
            .bg(divider_color)
    })
```

設定されたパネルごとに 1 つの `panel` を、順序どおりに指定します。`handle` は、各区切りをそのインデックスから
構築します。インデックスは、その直前のパネルのインデックスです。
`Axis::Horizontal` はパネルを左から右に配置してハンドルの幅を使用し、
`Axis::Vertical` は上から下に配置してハンドルの高さを使用します。フレームの
寸法に上限を与え、ハンドルには実際の太さを与えてください。サイズは、区切りの太さを除いた
使用可能な空間に対する比率で、合計が 1 になり、親がリサイズされても
比例関係を保ちます。フレームのパディングはサポートされており、内部のレイアウトには隙間がありません。

`ResizablePanel::new(default)` は 0 から 1 の間で自由な状態から始まります。`limits` は
展開時のサイズを制限し、`collapsible(size)` はそれより小さい折りたたみ時の
サイズを許可します。デフォルトがパネルの制約に違反する場合や
合計が 1 にならない場合、State の構築はパニックします。`pixel_limits(min..=max)` は、グループが測定された後に
適用される論理ピクセルの制限を追加し、比率の制限とピクセルの制限のうち厳しい方が
優先されます。測定された空間が変化したとき、新しい制限を破るレイアウトは
近いものから順に 1 度だけ調整し直され、Change を発行します。まだ有効なレイアウトは
比率を保ちます。空間がすべてのピクセル制限を満たせない場合、満たせるようになるまで、グループは
比率の制限のみを使用します。区切りの値と Home/End は
測定された制限を反映します。

区切りを動かすと、一方の側のパネルが大きくなり、反対側のパネルが
近いものから順に小さくなるため、最小サイズのパネルは移動を次の
パネルに渡します。どのパネルも吸収できない移動では、区切りはその場に留まります。折りたたみ可能なパネルの
最小サイズと折りたたみサイズの中間を越えてドラッグすると、スナップして
閉じ、その点を越えて戻すと最小サイズで再び開きます。

| 入力 | 結果 |
| --- | --- |
| 区切りをドラッグ | 実際の押下位置からリサイズし、制約の範囲内で連鎖します |
| 水平グループでの Left / Right | 区切りの前のパネルを 2 パーセントポイント縮小 / 拡大します |
| 垂直グループでの Up / Down | 区切りの前のパネルを 2 パーセントポイント縮小 / 拡大します |
| 折りたたまれたパネルに向かう矢印 | 最小サイズで再び開きます |
| 最小サイズの折りたたみ可能なパネルから離れる向きの矢印 | 折りたたみます |
| Home / End | 区切りの前のパネルに、許容される最小 / 最大のサイズを与えます |
| Enter | 区切りの前の折りたたみ可能なパネルを折りたたむ、または最後のサイズに戻します |
| Tab / Shift+Tab | 区切りとパネル内のコントロールを通常のドキュメント順に移動します |

Home、End、Enter は
[APG のウィンドウスプリッターパターン](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/)に従います。
リサイズのキーコンテキストを持つのは区切りだけです。パネル内のテキスト編集、選択、スクロールは
それぞれ独自の動作を保ちます。ポインターのドラッグは GPUI のドラッグの
ライフサイクルを使用し、所有する State と区切りを識別するため、独立した、またはネストした
グループが、他の区切りのドラッグに反応することはありません。

各区切りはネイティブの Splitter ロールを持ち、その数値、制限、ステップは
直前のパネルをパーセントで表します。ネイティブの向きは
区切り線を表します。各区切りには、調整するパネルを示すラベルを付け、
グリップの子要素は操作できないようにしてください。スタイルはすべてアプリケーションが指定します。

サイズ 0 に折りたたまれたパネルはコンテンツをアンマウントするため、フォーカス
ストップやアクセシビリティノードを持ちません。フォーカスが内部にあった場合は、隣の
区切りに移動します（リサイズが無効な間はグループ自体に移動します）。アイコンレールのような、0 でない折りたたみ
サイズでは、コンテンツはマウントされたままです。

プレゼンテーションを更新するには State を observe します。`sizes()`、`panel_count()`、
`is_collapsed(index)`、`axis()`、`handle_focus(index)`、`is_disabled()` が
その契約を公開します。`set_sizes` はレイアウト全体を置き換え、無効なものではパニックし、
その後、測定されたピクセル制限に合わせて調整します。レイアウトを永続化するには、
`ResizableEvent::Change` の `sizes()` をアプリケーションのストレージに保存し、
次の起動時に `set_sizes` に渡します。
`collapse(index)` と `expand(index)` は折りたたみ可能なパネルに作用し、隣のパネルが変化を
吸収できない場合は何もしません。レイアウトが変わるたびに、プログラムによる更新も含めて 1 回
`ResizableEvent::Change(sizes)` が発行されます。`set_disabled` は
ポインター、キーボード、アクセシビリティによるリサイズと通常の Tab の進入をブロックします。
フォーカスされた区切りはバインディングを保つため、Tab で離れられます。

Schedule のサンプルは、共有のノートを折りたたみ可能な最初のパネルに、
計画の表を 2 軸の ScrollArea 内の 2 番目のパネルに置き、後者は少なくとも 96 px を保ちます。
タブを閉じたり切り替えたりしても、
アプリケーションがそれらの State を保持しているため、テキストとサイズは保たれます。
ライブラリはファイルを書き込まず、保存先はアプリケーションが決めます。
