긴 메뉴는 창 높이에 맞게 스크롤됩니다. 방향키·Home·End·문자 검색으로 이동하면 활성 명령이 보입니다. ContextMenu, Menubar의 메뉴와 하위 메뉴에도 같은 동작이 적용됩니다.

DropdownMenu와 ContextMenu는 `MenuState`, `MenuItem`, `MenuEvent`,
`MenuOption`을 공유합니다. 공유 명령 동작은 열기/닫기 상태, 닫기, 순회, 포커스
복원에 Popover를 재사용합니다. 고정된 순서의 `MenuItem::new(value, label)` 항목으로
`MenuState::new(items, cx)`를 만듭니다. 값은 고유해야 하며, 사용할 수 없는 명령에는
`.disabled(true)`를 씁니다. 비어 있거나 모두 비활성화된 컬렉션은 열 수는 있지만
명령을 실행할 수는 없습니다.

`DropdownMenu::new(id, &state)`를 다음과 함께 렌더링합니다.

- `.trigger(|button| ...)`: 네이티브 트리거의 접근 가능한 이름과 모양.
- `.accessibility_label(...)`: 메뉴의 접근 가능한 이름.
- `.content(...)`: 항목마다 하나씩, 컬렉션 순서대로 `MenuOption::new(&state, index)`를
  담습니다. 텍스트, 간격, 색상 등 시각적 내용은 직접 제공합니다.
- `.anchor(...)`와 `.offset(...)`: 기존 팝업 배치를 구성합니다.

렌더링을 위해 상태를 관찰합니다. 활성 명령의 스타일에는 `highlighted_index()`를,
레이블과 비활성화 상태에는 `items()`를 읽습니다. 메뉴는 선택된 값을 유지하지
않습니다. 명령은 액션을 나타내며 반복해서 실행될 수 있습니다. 대화형 폼 컨트롤은
메뉴의 명령 내용 밖에 둡니다.

## 체크 명령

애플리케이션이 제어하는 체크박스 명령을 렌더링하려면 `MenuOption::checked(bool)`을
씁니다. 이 빌더를 생략하면 일반 `MenuItem`으로 남고, `.checked(false)`는 체크되지 않은
`MenuItemCheckBox`를, `.checked(true)`는 체크된 것을 노출합니다. 보이는 표시기와 체크
값은 애플리케이션이 렌더링할 때마다 제공합니다.

```rust
MenuOption::new(&menu, index)
    .checked(show_cursor)
    .child("Show cursor")
```

체크 명령은 일반 명령과 같은 탐색, 비활성화 동작, `MenuEvent::Action(value)`를
사용합니다. 활성화하면 이벤트를 전달하기 전에 메뉴를 닫고 포커스를 복원합니다.
애플리케이션이 그 액션을 처리하고 다음 체크 값을 렌더링합니다. MenuState는 체크
값을 저장하지도, 자동으로 토글하지도 않습니다. 제공하는 값을 바꿔도 액션은
디스패치되지 않습니다. 예제의 Show cursor와 Keep toolbar visible 명령은 Checkbox와
Switch가 쓰는 유지되는 애플리케이션 불리언을 공유합니다. DropdownMenu와 ContextMenu
모두 같은 메뉴 내용 조합으로 이 값을 렌더링합니다.

## 공유 상호작용과 생명주기

| 입력 | 동작 |
| --- | --- |
| 트리거 클릭 / Enter / Space / Down | 첫 번째 활성화된 명령에서 열기 |
| 트리거 Up | 마지막 활성화된 명령에서 열기 |
| 메뉴 Up / Down | 비활성화된 명령을 건너뛰고 순환하며 커서 이동 |
| 메뉴 Home / End | 첫 번째 / 마지막 활성화된 명령으로 이동 |
| 출력 가능한 문자 하나 | 대소문자를 무시하고 그 문자로 시작하는 활성 레이블을 순환 |
| 옵션 클릭 / 메뉴 Enter / Space | 명령을 한 번 실행하고 닫기 |
| Escape | 닫고 트리거 포커스 복원 |
| Tab / Shift-Tab | 닫고 Popover의 일반 포커스 순회로 빠져나감 |

타입어헤드는 한 번에 한 문자씩 일치시키며, 버퍼링된 검색이나 타이머는 없습니다.
Ctrl, Alt, 플랫폼, Fn 단축키는 이 검색에 들어가지 않습니다. 포인터 호버는 키보드
탐색과 같은 커서를 움직입니다. 비활성화된 명령은 계속 보이고 비활성화 메타데이터를
갖지만, 탐색에서 건너뛰며 실행할 수 없습니다.

애플리케이션에서 명령을 처리하려면 `MenuEvent::Action(value)`를 구독합니다. 메뉴는
이벤트를 전달하기 전에 닫히고 트리거를 복원합니다. 따라서 핸들러가 Dialog를 열 수
있고, 그 Dialog를 닫으면 나중에 메뉴 트리거로 돌아갑니다. 예제는 명령을 처리하면서
창을 받기 위해 `cx.subscribe_in`을 사용합니다.

상태 메서드에는 `open`, `close`, `set_disabled`, `focus_handle`,
`content_focus_handle`이 있습니다. `is_open(cx)`과 `is_disabled(cx)`는 조합된 Popover
상태를 읽으므로 `&App`을 받습니다. 팝업 생명주기의 소유자는 하나입니다. 옵션은 별도의
Tab 스톱이 아니며, 키보드 포커스는 메뉴 범위에 머물고 강조된 옵션이 활성 하위 항목을
제공합니다. 감싸는 Dialog는 여전히 Tab 순회를 제한하고, 바깥 포인터 누름은 일반
동작을 유지합니다.

닫혀 있는 동안에도 메뉴 호스트를 마운트해 둡니다. Popover와 같은 호스트 제거 포커스
계약이 적용됩니다. `check_state(CheckboxState::Indeterminate)`는 mixed 체크박스 명령을,
`radio_checked(bool)`은 MenuItemRadio 시맨틱을 제공합니다. 상호 배타적인 라디오 값,
그룹화, 렌더링은 애플리케이션이 소유합니다.

네이티브 메타데이터에는 펼침/비활성화 상태를 가진 Button 트리거, Menu 범위, 제공된
체크 상태를 가진 이름 있는 일반/체크박스/라디오 명령, 하위 메뉴 펼침 상태, 활성 하위
항목이 포함됩니다. 네이티브 has-popup 속성이나 트리거에서 메뉴로의 controls 관계는
내보내지 않습니다. 이 계약은 구현된 동작을 설명할 뿐, 접근성 패턴을 완전히 준수한다거나
스크린리더 검증을 마쳤다는 주장이 아닙니다.

## 하위 메뉴

자식 `MenuState` 엔터티를 부모보다 먼저 만듭니다. 부모 항목은 `.submenu(&child)`를
선언하고, 그 항목은 `.trigger(|option| ...)`와 자식의 옵션을 담은 `.content(...)`를
갖춘 `MenuSubmenu::new(&parent, index)`로 렌더링합니다. 하위 메뉴 호스트가 팝업 배치를
소유하고 자식의 기존 Popover 생명주기를 재사용합니다. 메뉴 트리에는 순환이 없어야
하며, 자식은 하나의 부모에만 속합니다.

하위 메뉴 행에 네이티브 포커스가 가면 부모 메뉴의 강조 항목이 동기화됩니다. 펼침
방향 화살표는 강조된 하위 메뉴를 열고, 반대 방향 화살표나 Escape는 하위 메뉴 하나를
닫고 부모 메뉴 범위를 복원합니다. 포인터 호버는 해당 자식을 열고 형제 분기를 닫습니다.
일반 말단 항목을 활성화하면 트리 전체가 닫히고 루트 상태에서 `MenuEvent::Action`이
정확히 한 번 발생합니다. Tab/Shift-Tab은 루트 Popover 순회를 통해 메뉴 트리 전체를
빠져나갑니다. 애플리케이션은 루트를 구독하고 말단 액션과 체크/라디오 값을 소유합니다.
닫혀 있는 동안에도 모든 호스트를 조합 안에 유지합니다.
