タブのファミリーは `TabsState`、`TabList`、`Tab`、`TabPanel` で構成されます。

1. 固定された順序付きの `TabItem::new(value, label)` エントリで `TabsState::new(items, cx)` を作成します。
   値は一意でなければなりません。利用できないエントリには `.disabled(true)` を指定します。
2. 最初の有効なタブが選択された状態で始まります。別の有効な項目を選択するには `.default_value(value)` を使用します。
   不明な、または無効なデフォルトは設定エラーでありパニックします。空のコレクションやすべてが無効なコレクションには、
   アクティブなパネルがありません。
3. アクセシブルなラベルを付けて `TabList::new(id, &state)` を描画し、各項目に対して順序どおりに
   `Tab::new(&state, index)` を 1 つずつ描画します。
4. 対応する `TabPanel::new(&state, index)` 要素をリストの隣に描画します。通常の
   GPUI の `div` でリストとパネルを配置できます。追加で必須となるルートの
   ラッパーや、強制されるレイアウトはありません。

各タブは、ロール、ラベル、selected/disabled のメタデータ、安定したフォーカスハンドル、
アクティブ化を提供します。視覚的な内容はアプリケーションが指定します。State は
`items()`、`selected_index()`、`selected_item()`、`tab_focus_handle(index)`、
`panel_focus_handle(index)` を公開します。利用側のビューを再描画するには State を observe し、
選択の変更には `TabsEvent::Change(value)` を購読します。現在のタブを選択しても、
重複したイベントは発行されません。

`select_value(value, window, cx)` は、キーボードフォーカスを移さずに有効な項目を選択します。
選択が変わったときにのみ `true` を返して 1 回 `TabsEvent::Change` を発行し、
不明な値、無効な値、すでに選択されている値では、イベントなしで `false` を返します。
関連する再描画のために State を observe してください。別の項目の選択によって、現在フォーカスされている
コンテンツが削除される場合は、呼び出し側が、保持されているナビゲーションエントリまたは他の有効な対象にフォーカスを移さなければなりません。
このメソッドはその対象を選ぶことも、通常のナビゲーション用 Button を Tab に変えることもしません。

TabList のアクティブ化はデフォルトで自動です。有効なタブにフォーカスを移すとそのタブも
選択されます。これにはプログラムやアクセシビリティによるフォーカスも含まれます。フォーカスと選択を独立させるには
`TabsState::new(items, cx).manual_activation()` を設定します。手動モードでは、矢印キーと Home/End が
現在のパネルをマウントしたままフォーカスを移動し、クリック、Enter、Space でフォーカスされたタブを確定します。各リストには
Tab ストップが 1 つあり、自動モードでは選択されたタブ、手動モードでは最後にフォーカスされたタブ
（最初は選択されたタブ）です。`select_value` は手動モードのフォーカスの進入を保ちます。
カタログは手動のアクティブ化を使用し、Compact のセッションタブは自動のままです。

| 入力 | 水平リスト | 垂直リスト |
| --- | --- | --- |
| Left / Right | 前 / 次の有効なタブ | タブを変更せずに伝播します |
| Up / Down | タブを変更せずに伝播します | 前 / 次の有効なタブ |
| Home / End | 最初 / 最後の有効なタブ | 最初 / 最後の有効なタブ |
| Enter / Space | フォーカスされたタブをアクティブ化します | フォーカスされたタブをアクティブ化します |
| Tab / Shift-Tab | タブリストから離れます | タブリストから離れます |

矢印キーによる移動は端で循環し、無効なエントリをスキップします。リストの
向きは `.axis(Axis::Horizontal)` または `.axis(Axis::Vertical)` で設定し、
通常の GPUI のレイアウトメソッドで配置します。向きは視覚的なレイアウトを選択しません。

マウントされるのはアクティブなパネルだけです。非アクティブなパネルは、レイアウト、フォーカス
ストップ、アクセシビリティノードを持ちません。パネルが削除されて再び描画されても値が保たれるよう、
フォームデータと保持された input エンティティはアプリケーションのビューで保持してください。

デフォルトでは、パネルは独自の Tab ストップを持たないフォーカススコープであり、Tab でその
インタラクティブな子要素に入れます。静的なテキストだけを含むパネルなど、パネル自体がフォーカスを受け取る必要がある場合は
`.tab_stop(true)` を使用します。パネルのアクセシブルな
ラベルはそのタブに由来します。固定された GPUI API は、ロール、ラベル、selected
状態を公開しますが、公開された兄弟ノードの関係を扱う API はないため、ネイティブの明示的な
タブからパネルへの controls/labelled-by 関係は出力されません。ネイティブのスクリーン
リーダーの動作には、依然としてデスクトップでの検証が必要です。

Sidebar レシピは、専用の `TabsState` の固定された項目、選択された値、安定した
フォーカスハンドルを再利用し、TabList の自動選択ではなく明示的な Button のアクティブ化を使用します。
この用途には新しい State を作成してください。TabList は保持されたフォーカスの購読を
インストールするため、以前に TabList にバインドされた State を Sidebar と共有したり、
Sidebar に付け替えたりしてはいけません。Settings のサンプルをリサイズしても、
Sidebar とコンテンツが再配置されるだけで、TabList に置き換わることはありません。

`Button::current(true)` は、選択されたナビゲーション用 Button にネイティブの
`AriaCurrent::Page` を付けます。デフォルトの false ではそのプロパティは省略されます。このメソッドは
スタイルとフォーカスを変更しません。`Button::selected(...)` とアプリケーションの
移動先ハンドラーが、それらを別々に制御します。Sidebar は、TabList/Tab/TabPanel のロールではなく、
ネイティブの Navigation/Button/Region のセマンティクスを保ちます。
