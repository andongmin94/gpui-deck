DatePicker는 기존 Calendar를 Popover의 트리거, 배치, 닫기, 포커스 생명주기에
연결합니다. 선택된 날짜의 소유자는 여전히 Calendar 하나뿐입니다. 범위와 선택적
초기값으로 Calendar를 만든 다음, 같은 창에서 picker를 한 번 생성합니다.

```rust
let picker = cx.new(|cx| DatePickerState::new(&calendar, window, cx));
```

렌더링을 위해서는 picker를 관찰합니다. picker가 Calendar와 Popover를 모두 관찰하므로
같은 뷰에서 Calendar를 따로 관찰할 필요가 없습니다. 선택은 `selection(cx)`로,
중첩된 날짜 상태는 `calendar()`로 접근합니다. Calendar는 이 picker의 팝업 안에서만
렌더링하고, 별도의 독립 그리드에서 동시에 렌더링하지 않습니다.

```rust
DatePicker::new("recording-date", &picker)
    .accessibility_label("Choose recording date")
    .offset(px(6.))
    .trigger(|button| {
        button
            .accessibility_label(format!("Recording date, {formatted_date}"))
            .child(formatted_date)
    })
    .content(calendar_surface)
```

애플리케이션은 형식화된 트리거 텍스트, 달력/월 컨트롤, 팝업의 크기와 모양을
제공합니다. `accessibility_label`은 팝업의 이름을 지정하며, Button 트리거의 이름은
따로 지정합니다. 일반적인 CalendarDay 활성화만으로 선택이 완료되므로, 애플리케이션이
모든 날짜에 클릭 후 닫기 핸들러를 중복해서 달 필요는 없습니다. 일반적인 Tab 순회와
감싸는 Dialog의 포커스 가두기는 계속 Root가 담당합니다.

| 동작 | 결과 |
| --- | --- |
| 선택된 날짜가 있을 때 열기 | 탐색 위치를 그 날짜로 재설정하고 현재 그리드 슬롯에 포커스 |
| 선택 없이 열기 | Calendar의 마지막 탐색 날짜를 유지하고 포커스 |
| 일/월 탐색 | 확정된 날짜는 바꾸지 않고 탐색 위치만 변경 |
| 단일 날짜 활성화 | 선택하고 닫은 뒤 트리거로 복원하며, 같은 날짜를 다시 골라도 닫힘 |
| 부분 범위 / 다중 날짜 활성화 | 선택을 갱신하고 팝업을 연 상태로 유지 |
| 완성된 범위 활성화 | 변경된 범위를 내보내기 전에 닫고 트리거로 복원 |
| Escape | 감싸는 Dialog보다 먼저 picker를 닫고 선택은 유지 |
| 팝업 내용을 지나치는 Tab / Shift+Tab | 닫고 트리거 위치에서 이어서 이동 |
| 바깥 클릭 | 닫으면서 바깥 컨트롤이 새로 받은 포커스를 유지 |

월이 바뀌면 선택된 날짜가 다른 포커스 슬롯으로 옮겨질 수 있으므로, 날짜 포커스는
열기 직전에 결정합니다. `DatePickerEvent::Change`는 사용자가 실제로 선택을 바꿨을
때만 발생합니다. 단일 값과 완성된 범위 값은 이벤트 전에 팝업을 닫으므로, 구독자가
다른 화면을 열어도 새 포커스를 잃지 않습니다. 부분 범위와 다중 값은 열린 상태에서
게시됩니다. 공개 Calendar Change 동작은 계속 중복이 제거되며, 이 조합은 같은 날짜의
성공적인 활성화도 관찰합니다.

`open`과 `close`는 명령형 생명주기 제어를 제공합니다. `set_disabled`는 열린 팝업을
닫고 트리거와 Calendar를 모두 비활성화합니다. 중첩된 달력을 따로 수정하지 말고 이
메서드로 비활성화 상태를 맞춥니다. `set_selection(selection, window, cx)`는 전체
선택을 검증하고 팝업을 닫은 뒤 Change를 내보내지 않고 Calendar를 갱신합니다.
잘못된 값은 picker를 바꾸지 않습니다. 애플리케이션은 프리셋 Button에도 같은 setter를
쓸 수 있으며, Selection 카탈로그에는 완성된 범위 프리셋이 있습니다.

## 입력된 날짜

`parse_date_text(text, today)`는 picker 옆의 일반 Input에 입력된 날짜 하나를 읽습니다.
`-`, `/`, `.` 구분자를 쓰는 `YYYY-MM-DD`와 대소문자를 구분하지 않는 영어 형식
`today`, `tomorrow`, `yesterday`, `in N days|weeks`, `N days|weeks ago`(단수 단위 포함)를
받습니다. 라이브러리에는 시계가 없으므로 애플리케이션이 `today`를 전달합니다.
존재하지 않는 날짜와 그 밖의 텍스트는 `None`을 반환합니다. 결과는 `set_selection`으로
적용하며, 이때도 Calendar의 범위와 비활성화된 날짜가 적용됩니다.

```rust
let date = parse_date_text(&input.read(cx).value(), today);
let applied = date.is_some_and(|date| {
    picker.update(cx, |picker, cx| {
        picker.set_selection(CalendarSelection::Single(Some(date)), window, cx)
    })
});
```

Schedule 예제는 picker 뒤에 "Type a date" Field를 추가합니다. Enter를 누르면 예제의
고정 날짜를 기준으로 텍스트를 적용하고 ISO 텍스트로 다시 씁니다. 읽을 수 없거나
선택할 수 없는 날짜는 다음 편집 전까지 Field 오류를 표시합니다. picker와 필드는
별개의 Tab 스톱으로 유지됩니다.

picker는 애플리케이션이 형식화한 Button 트리거와 함께 단일, 다중, 범위 날짜를
지원합니다. 프리셋을 가져오거나, 다른 언어 또는 "next Friday" 같은 자유 형식 문구를
해석하거나, Calendar 계약을 넘어서는 로캘/시간대 규칙을 추가하지는 않습니다.
