title: Input OTP
description: "1 つの数値エディター、ネイティブの選択/貼り付け/削除/元に戻す、桁スロット、完了イベントを提供します。"

`InputOtpState::new(length, window, cx)` は、0 でない固定のスロット数と、ASCII 数字/長さのバリデーターを持つ、
保持された 1 つの `InputState` を作成します。`InputOtp` は、アプリケーションが指定するスロットを
`.slot(|slot, window, cx| ...)` で描画します。各スロットは、そのインデックス、文字、アクティブ/選択状態、
無効/読み取り専用のフラグを受け取ります。
これらの情報を、枠線、グループ化、選択の表示に使用してください。スロットのクリックは
同じエディター内の位置を選択し、input の Tab ストップとネイティブの
アクセシビリティの所有者は 1 つだけです。

ネイティブの貼り付け、選択、矢印キーによる移動、Backspace/Delete、元に戻す操作は
既存のエディターが担当します。貼り付けた結果の値全体が数字であり、収まる必要があります。
テキストが暗黙に切り詰められたり、別々のエディターに振り分けられたりすることはありません。
`InputOtpEvent` は、編集後の `value` とすべてのスロットが埋まっているかどうかを通知します。
`set_value` はプログラムによる置き換えを検証し、`input()` は、バリデーターを変更せずに既存の Enter/フォーカスの連携で使えるよう、
保持されたエディターを公開します。
完了は長さの条件であり、検証はアプリケーションが管理します。

カタログの Forms and feedback ビューはローカルのコード `742915` を使用します。入力を
完了すると Review session が有効になり、実際の確認用 Drawer が開きます。確認すると
モーダルを閉じてから、時間制限付きの Toast を Toaster に追加します。コードが一致しない場合も
通知が積み重ねられます。コードを編集すると、ローカルの確認状態がクリアされます。
リモートでの検証や通信は一切関与しません。
