`PopoverState` は、開閉状態、トリガーのフォーカス、ポップアップのフォーカススコープ、無効
状態を管理します。`cx.new(PopoverState::new)` で一度だけ作成し、レンダリングのために observe します。
ポップアップ内のコントロールには、任意で `.with_initial_focus(&handle)` を使用します。
そうでない場合、開くとコンテンツのスコープにフォーカスし、Tab で最初のコントロールに入ります。

`Popover::new(id, &state)` を次のように構築します。

- `.trigger(|button| ...)` で、既存の Button API を使ってトリガーの内容、アクセシブルな名前、
  外観を指定します。
- `.accessibility_label(...)` で、ポップアップの非モーダルなダイアログサーフェスに名前を付けます。
- `.content(...)` で、アプリケーションが管理するポップアップの内容とサーフェスのスタイルを指定します。
- `.anchor(...)` で角へのアンカーを、`.offset(...)` でトリガーとの間隔を指定します。
- `.side(Placement::Right).align(Align::Start)` で、衝突時に反転する、辺に配置されるポップアップを指定します。
  `.align(...)` だけを呼び出すと Bottom が選ばれます。辺に対するデフォルトの整列は
  Center です。Top/Bottom の Start/End は、スコープ付きの論理的な方向に従います。ポジショナーは
  トリガーの現在のフレームを追跡し、ビューポートに制限します。明示的な角のアンカーと
  コンテキストメニューのポインター座標は、それぞれ独自の配置の契約を保ちます。

ライブラリは、トリガーの操作、フォーカス、無効状態、expanded の
メタデータを管理します。指定された `id` がそのトリガーを識別します。そのボタンのビルダーは
外観とアクセシブルな名前を提供する必要があり、ポップアップ内のアプリケーションのボタンは
`PopoverState::close(window, cx)` を呼び出せます。

State のメソッドには `open`、`close`、`is_open`、`is_disabled`、
`set_disabled(disabled, window, cx)`、`focus_handle`、`content_focus_handle` があります。
無効にすると開いているポップアップが閉じ、再び開けなくなります。閉じている間も Popover はマウントしたままにして、
トリガーが同一性を保ち、アンカーのジオメトリを
測定できるようにしてください。

Popover は非モーダルであり、フォーカスを閉じ込めません。Tab はその内容を巡った後、
トリガーの次の通常のコントロールに移動し、ポップアップを閉じます。最初のコンテンツのコントロールより前での Shift-Tab は、
ポップアップを閉じてトリガーに戻ります。それを含む
Dialog は引き続きその移動を制限します。

Escape はフォーカスされたポップアップを閉じ、トリガーのフォーカスを復元します。Popover が
Dialog の内側にある場合、最初の Escape では親のダイアログは開いたままです。外側でのポインター押下は、
クリックされたコントロールがフォーカスを受け取れるようにしつつ、ポップアップを閉じます。フォーカスが
他へ移った場合、親サーフェスが閉じた場合、ウィンドウが非アクティブになった場合も閉じます。
別のサーフェスがフォーカスを取った後で、ポップアップがフォーカスを引き戻すことはありません。

アプリケーションが、トリガーを含め、フォーカスされた Popover ホスト全体を削除する場合は、
その更新の一環として、残っているコントロールにフォーカスを移さなければなりません。
ポップアップは、任意の置換先を選ぶことなく、開いた状態をクリーンアップします。
サンプルのタブの切り替えと Dialog の閉鎖は、ポップアップのサーフェスを削除する前に
すでにフォーカスを移しています。
