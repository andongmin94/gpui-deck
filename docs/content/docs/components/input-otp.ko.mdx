`InputOtpState::new(length, window, cx)`는 0이 아닌 고정 슬롯 수와 ASCII 숫자/길이
검증기를 가진 유지되는 `InputState` 하나를 만듭니다. `InputOtp`는
`.slot(|slot, window, cx| ...)`로 애플리케이션이 제공하는 슬롯을 그립니다. 각 슬롯은
인덱스, 문자, 활성/선택 상태, 비활성화/읽기 전용 플래그를 받습니다. 이 정보로 테두리,
그룹화, 선택 화면 표현을 구성합니다. 슬롯을 클릭하면 같은 편집기 안의 위치가 선택되며,
입력 Tab 스톱과 네이티브 접근성 소유자는 하나뿐입니다.

네이티브 붙여넣기, 선택, 화살표 탐색, Backspace/Delete, 실행 취소는 기존 편집기가
계속 담당합니다. 붙여넣은 결과 값 전체가 숫자여야 하고 길이에 맞아야 하며, 텍스트를
조용히 잘라내거나 여러 편집기에 나눠 넣지 않습니다. `InputOtpEvent`는 편집된 `value`와
모든 슬롯이 채워졌는지를 알립니다. `set_value`는 프로그래밍 방식의 교체를 검증하고,
`input()`은 검증기를 바꾸지 않은 채 기존 Enter/포커스 통합을 위해 유지되는 편집기를
노출합니다. 완료는 길이 조건일 뿐이며, 검증은 애플리케이션이 소유합니다.

카탈로그의 Forms and feedback 뷰는 로컬 코드 `742915`를 사용합니다. 입력을 마치면
Review session이 활성화되어 실제 확인 Drawer가 열리고, 확인하면 모달을 닫은 뒤
Toaster에 시간 제한이 있는 Toast를 띄웁니다. 코드가 일치하지 않을 때도 알림이 쌓입니다.
코드를 편집하면 로컬 확인 상태가 지워집니다. 원격 검증이나 전송은 관여하지 않습니다.
