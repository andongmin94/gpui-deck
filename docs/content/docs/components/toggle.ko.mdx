title: Toggle과 Toggle Group
description: "Button의 활성화, 포커스, 비활성화 동작 위에 제어되는 눌림 상태를 제공합니다."

`Toggle::new(id).pressed(bool)`은 제어되는 토글 버튼입니다. 기존 Button을 조합해
네이티브 클릭/Enter/Space 활성화, 비활성화 동작, 포커스를 재사용합니다. 추가되는
계약은 눌림 접근성 상태와 `on_change(next_pressed, event, window, cx)`입니다.
애플리케이션은 그 값을 저장하고, 뷰에 알리며, 콘텐츠와 눌림 상태 스타일을
제공합니다. 안정적인 레이블은 액션의 이름을 지정하고, 눌림 메타데이터는 현재 상태를
설명합니다.

Toggle은 일반 GPUI 스타일과 자식 외에 `accessibility_label`, `disabled`,
`track_focus`, `tab_index`, `tab_stop`을 받습니다.

함께 누를 수 있는 독립적인 옵션에는, 고유한 값을 가진 고정된 순서의
`ToggleItem::new(value, label)` 항목으로 `ToggleGroupState::new(items, cx)`를
생성합니다. 사용할 수 없는 항목은 `.disabled(true)`로 표시하고, 필요하면
`.default_values([values])`를 설정합니다. 기본값은 활성화된 항목을 가리켜야
합니다. 기본값을 지정하지 않으면 선택이 비어 있는 상태로 시작합니다. 선택적인
배타적 선택에는 `.single_selection()`을 사용합니다. 다른 옵션을 활성화하면 이전
값을 대체하고, 눌린 옵션을 활성화하면 선택이 해제됩니다. `.single_selection()`과
`.default_values(...)`의 호출 순서와 관계없이, 단일 선택의 기본값에는 서로 다른
값이 최대 하나만 들어갈 수 있습니다.

`ToggleGroup::new(id, &state).accessibility_label(...)`를 렌더링하고, 각 항목마다
`ToggleOption::new(&state, index)`를 하나씩 렌더링합니다. 각 옵션은 Toggle을
조합합니다. 그룹은 Group 역할과 방향을 제공하고, 레이아웃은 애플리케이션 코드가
별도로 제공합니다. 현재 화면 표현에는 `items()`, `is_pressed(index)`,
`selected_values()`를 읽습니다. 선택된 집합의 변경에는 엔티티를 관찰하고
`ToggleGroupEvent::Change(values)`를 구독합니다. 값은 원래 항목 순서를 따릅니다.

`set_selected_values(values, window, cx)`는 사용자 이벤트, 포커스 변경, 커서 변경
없이 눌린 집합을 교체합니다. 중복된 값은 하나로 합쳐지고, 빈 이터레이터는 선택을
지웁니다. 알 수 없거나 비활성화된 값, 또는 단일 모드에서 서로 다른 여러 값은 아무것도
바꾸지 않고 false를 반환합니다. 그룹이 비활성화된 동안에도 애플리케이션 갱신은
허용됩니다. 세션 예제는 초기 라디오 값과 서식 값을 이러한 유지되는 상태 설정자로
적용합니다.

그룹에는 Tab 스톱이 하나 있으며, 마지막으로 포커스된 활성화된 옵션 또는 처음에는
첫 번째 활성화된 옵션에 놓입니다. 가로 방향의 Left/Right 또는 세로 방향의 Up/Down은
활성화된 옵션 사이를 이동하며 순환합니다. Home/End는 첫 번째/마지막 활성화된 옵션으로
이동합니다. 다른 축의 키는 전파됩니다. 포커스 이동은 선택된 집합을 바꾸지 않으며,
클릭, Enter, Space는 선택 모드에 따라 포커스된 옵션을 토글합니다. Tab은 그룹을
떠납니다.

`set_disabled(disabled, window, cx)`는 선택을 유지한 채 그룹 전체를 비활성화합니다.
`option_focus_handle(index)`는 안정적인 옵션 포커스를 노출합니다. RadioGroup은
화살표 내비게이션 중 즉시 선택되는 배타적 선택을 제공하고, ToggleGroup은 두 모드
모두에서 포커스 이동을 선택과 독립적으로 유지합니다. 세션 예제는 독립적인 굵게/기울임
요약 텍스트 스타일을 사용하고, 카탈로그는 선택적인 Center/End 문서 정렬에 단일 선택을
사용합니다.
