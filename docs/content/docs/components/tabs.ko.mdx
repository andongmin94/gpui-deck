탭 계열은 `TabsState`, `TabList`, `Tab`, `TabPanel`로 구성됩니다.

1. 고정된 순서의 `TabItem::new(value, label)` 항목으로 `TabsState::new(items, cx)`를
   생성합니다. 값은 고유해야 합니다. 사용할 수 없는 항목은 `.disabled(true)`로 표시합니다.
2. 첫 번째 활성화된 탭이 선택된 상태로 시작합니다. 다른 활성화된 항목을 선택하려면
   `.default_value(value)`를 사용합니다. 알 수 없거나 비활성화된 기본값은 구성
   오류이며 panic이 발생합니다. 비어 있거나 전부 비활성화된 컬렉션에는 활성 패널이 없습니다.
3. 접근 가능한 레이블과 함께 `TabList::new(id, &state)`를 렌더링하고, 각 항목마다
   순서대로 `Tab::new(&state, index)`를 하나씩 렌더링합니다.
4. 대응하는 `TabPanel::new(&state, index)` 요소를 목록 옆에 렌더링합니다. 일반
   GPUI `div`로 목록과 패널을 배치할 수 있습니다. 추가로 필요한 루트 래퍼나 강제되는
   레이아웃은 없습니다.

각 탭은 역할, 레이블, 선택/비활성화 메타데이터, 안정적인 포커스 핸들, 활성화를
제공합니다. 시각적 콘텐츠는 애플리케이션이 제공합니다. 상태는 `items()`,
`selected_index()`, `selected_item()`, `tab_focus_handle(index)`,
`panel_focus_handle(index)`를 노출합니다. 사용하는 뷰를 다시 그리려면 상태를
관찰하고, 선택 변경에는 `TabsEvent::Change(value)`를 구독합니다. 현재 탭을 다시
선택해도 중복 이벤트는 발생하지 않습니다.

`select_value(value, window, cx)`는 키보드 포커스를 옮기지 않고 활성화된 항목을
선택합니다. 선택이 바뀔 때만 `true`를 반환하고 `TabsEvent::Change`를 한 번
발생시킵니다. 알 수 없거나, 비활성화되었거나, 이미 선택된 값은 이벤트 없이
`false`를 반환합니다. 그에 따른 다시 그리기에는 상태를 관찰합니다. 다른 항목을
선택해 현재 포커스된 콘텐츠가 제거되면, 호출자가 포커스를 유지되는 내비게이션
항목이나 다른 유효한 대상으로 옮겨야 합니다. 이 메서드는 그 대상을 고르지 않으며,
일반 내비게이션 Button을 Tab으로 바꾸지도 않습니다.

TabList의 활성화는 기본적으로 자동입니다. 활성화된 탭으로 포커스가 옮겨 가면
프로그래밍 방식이나 접근성 포커스를 포함해 그 탭도 선택됩니다. 포커스와 선택을
독립적으로 유지하려면 `TabsState::new(items, cx).manual_activation()`으로
구성합니다. 수동 모드에서는 화살표와 Home/End가 포커스를 옮기는 동안 현재 패널이
마운트된 상태로 남고, 클릭, Enter, Space가 포커스된 탭을 확정합니다. 각 목록에는
Tab 스톱이 하나 있습니다. 자동 모드에서는 선택된 탭, 수동 모드에서는 마지막으로
포커스된 탭(처음에는 선택된 탭)입니다. `select_value`는 수동 포커스 진입 지점을
유지합니다. 카탈로그는 수동 활성화를 사용하고, Compact의 세션 탭은 자동으로 남아
있습니다.

| 입력 | 가로 목록 | 세로 목록 |
| --- | --- | --- |
| Left / Right | 이전 / 다음 활성화된 탭 | 탭을 바꾸지 않고 전파 |
| Up / Down | 탭을 바꾸지 않고 전파 | 이전 / 다음 활성화된 탭 |
| Home / End | 첫 번째 / 마지막 활성화된 탭 | 첫 번째 / 마지막 활성화된 탭 |
| Enter / Space | 포커스된 탭 활성화 | 포커스된 탭 활성화 |
| Tab / Shift-Tab | 탭 목록을 떠남 | 탭 목록을 떠남 |

화살표 이동은 양 끝에서 순환하며 비활성화된 항목을 건너뜁니다. 목록의 방향은
`.axis(Axis::Horizontal)` 또는 `.axis(Axis::Vertical)`로 설정하고, 배치는 일반
GPUI 레이아웃 메서드로 합니다. 방향이 시각적 레이아웃을 정하지는 않습니다.

활성 패널만 마운트됩니다. 비활성 패널은 레이아웃, 포커스 스톱, 접근성 노드를
제공하지 않습니다. 패널이 제거되었다가 다시 렌더링되어도 값이 남도록, 폼 데이터와
유지되는 입력 엔티티는 애플리케이션 뷰에 보관합니다.

기본적으로 패널은 자체 Tab 스톱이 없는 포커스 범위이며, Tab으로 그 안의 상호작용
가능한 자식에 진입할 수 있습니다. 정적 텍스트만 담은 패널처럼 패널 자체가 포커스를
받아야 하면 `.tab_stop(true)`를 사용합니다. 패널의 접근 가능한 이름은 해당 탭에서
옵니다. 고정된 GPUI API는 역할, 레이블, 선택 상태는 노출하지만 공개된 형제 노드
관계 API는 노출하지 않으므로, 탭과 패널 사이의 명시적인 네이티브
controls/labelled-by 관계는 내보내지 않습니다. 네이티브 스크린리더 동작은 여전히
데스크톱에서 검증해야 합니다.

Sidebar 레시피는 전용 `TabsState`의 고정 항목, 선택된 값, 안정적인 포커스 핸들을
재사용하되, TabList의 자동 선택 대신 명시적인 Button 활성화를 사용합니다. 이
용도에는 새 상태를 만듭니다. TabList는 유지되는 포커스 구독을 설치하므로, 이전에
TabList에 바인딩된 상태를 Sidebar와 공유하거나 Sidebar로 옮겨서는 안 됩니다.
Settings 예제의 크기를 바꾸면 Sidebar와 콘텐츠의 배치만 바뀌며, 이를 TabList로
교체하지는 않습니다.

`Button::current(true)`는 선택된 내비게이션 Button에 네이티브
`AriaCurrent::Page`를 표시합니다. 기본값 false는 이 속성을 생략합니다. 이 메서드는
스타일과 포커스를 바꾸지 않으며, 그런 부분은 `Button::selected(...)`와
애플리케이션의 목적지 핸들러가 별도로 제어합니다. Sidebar는 TabList/Tab/TabPanel
역할 대신 네이티브 Navigation/Button/Region 시맨틱을 유지합니다.
