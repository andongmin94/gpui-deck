ビューで GPUI の ScrollHandle を保持し、ビューポートにスクロール軸方向の範囲を限定したサイズを与えます。
同じハンドルが、ネイティブのホイール/トラックパッドによるスクロールと
既存のオーバーレイスクロールバーを駆動します。

```rust
// Store once in the view, not on each render.
let scroll = gpui::ScrollHandle::new();

ScrollArea::new("session-list", &scroll)
    .accessibility_label("Sessions")
    .h(px(240.))
    .w_full()
    .content_styles(|style| style.flex().flex_col())
    .children(rows)
```

デフォルトの軸は垂直です。他の内容には `.axis(ScrollbarAxis::Horizontal)` または `Both` を使用します。
はみ出す内容には、最小/固定の大きさを与えるか、必要に応じて
縮小を防いでください。通常の GPUI スタイルで外側のフレームのサイズと装飾を指定します。
ビューポートの子のレイアウト、間隔、パディングには `content_styles` を使用します。ビューポートと
オーバーレイスクロールバーは GPUI の通常のレンダリングを使用するため、
祖先の可視性と不透明度が両方に適用されます。

`scrollbar_mode` は、既存の Scrolling、Hover、Always のモードを受け付けます。
`scrollbar_styles` は既存の型付きのトラック/つまみのスタイルを使用します。バーは
コンテンツに重なり、余白を確保しないため、コンテンツをバーに重ねたくない場合は、アプリケーションのパディングを残してください。たとえば、
計画の表は、リサイズ可能なビューポートに下/右のパディングと常に表示されるスクロールバーを使用しています。

公開されるフレームはネイティブの ScrollView ロールを公開し、アクセシブルなラベルを受け付けます。
独立したフォーカスストップやキーバインディングは追加しません。input の矢印キーは
テキストの編集を続け、Calendar の矢印キーは日付のナビゲーションを続けます。単純な静的コンテンツは
ポインターまたは保持されたハンドルでスクロールできます。独立したキーボードによるスクロール
コントロールは、この契約には含まれません。

子孫は、プリペイント中に GPUI のネイティブの `request_autoscroll` を使って
表示領域への移動を要求できます。Input、Textarea、Calendar、新たにフォーカスされた Button コントロールは、
必要に応じて要求を発行します。
ScrollArea は有効な軸のオフセットを制限し、ビューポートを動かす必要があるときに
新しいフレームを要求します。ネストした領域で調整された要求は祖先へ引き継がれ、
兄弟の保留中の要求は、誤ったビューポートのスクロールに使われることなく保持されます。
無効な軸のオフセットはクリアされます。

ScrollArea は GPUI の通常のスクロールと、保持された Scrollbar のポインターの
実装を再利用します。子の仮想化、弾性スクロールの追加、
ストリーミング/トランスクリプトのコンテンツのアンカーは行いません。
