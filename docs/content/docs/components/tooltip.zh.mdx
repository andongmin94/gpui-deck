将 `TooltipState::new(&trigger_focus, window, cx)` 与现有的
Button 焦点句柄一起保留。渲染 `Tooltip::new(id, &state, description)`，并通过
`.trigger(|button| ...)` 配置 Button。这会保留应用的
激活处理程序和焦点标识。Tooltip 上普通的 Styled 方法
用于配置非交互式的界面；触发器构建器负责按钮的
外观。不需要额外的初始化调用或按键绑定。

键盘焦点会立即显示文本；指针悬停则等待 500 毫秒。离开
会取消待处理的悬停。失焦、激活、窗口失去活动状态和 Escape 会关闭
它，且不移动焦点。Escape 会抑制重新打开，直到再次出现焦点或
指针进入。取消一个待处理且尚未显示的提示，会使 Escape 仍可供
外层界面使用。Enter 和 Space 仍会激活 Button 一次。卸载
触发器会取消待处理的悬停任务并重置保留的可见性。

触发器始终在其原生节点上暴露该描述。显示的文本
具有 Tooltip 角色，且没有 Tab 停靠点。GPUI 原生的工具提示层负责定位、
窗口边缘限制和绘制；该组件则添加焦点/悬停生命周期。
其已挂载的 Escape 订阅属于该窗口，不会发出
可能关闭另一个工具提示的全局清除操作。

`.content(|window, cx| ...)` 会用非交互式的富内容替换可见文本，
例如标题加弱化的详情行，或带键帽的标签。该
构建器在可见界面每次渲染时运行。纯文本描述
仍然是触发器的原生描述以及界面的 Tooltip 名称，因此
请使其与富内容所显示的内容保持等价的摘要。富内容不添加
Tab 停靠点。请不要在其中放置可聚焦或可点击的控件：工具提示会
在指针离开触发器时关闭。交互式预览应放在
HoverCard 或 Popover 中。

交互式的工具提示内容、触摸长按行为以及可配置的
提供者不属于此约定。示例用富标题和详情行包装了其现有的 Edit
session 按钮，因此同一个按钮会打开
设置 Dialog，并仍是其返回焦点的目标。
