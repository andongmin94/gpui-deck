기존 Button 포커스 핸들과 함께 `TooltipState::new(&trigger_focus, window, cx)`를
유지합니다. `Tooltip::new(id, &state, description)`을 렌더링하고
`.trigger(|button| ...)`로 Button을 구성합니다. 이렇게 하면 애플리케이션의
활성화 핸들러와 포커스 정체성이 보존됩니다. Tooltip의 일반 Styled 메서드는
비상호작용 표면을 구성하며, 버튼 모양은 트리거 빌더가 소유합니다. 추가 init 호출이나
키 바인딩은 필요하지 않습니다.

키보드 포커스는 텍스트를 즉시 표시하고, 포인터 호버는 500 ms를 기다립니다. 떠나면
대기 중인 호버가 취소됩니다. 블러, 활성화, 창 비활성화, Escape는 포커스를 옮기지
않고 툴팁을 닫습니다. Escape는 다음 포커스나 포인터 진입이 있을 때까지 다시 열리는
것을 막습니다. 아직 표시되지 않은 대기 중인 힌트를 취소하면 Escape는 바깥 표면이
사용할 수 있도록 남습니다. Enter와 Space는 여전히 Button을 한 번 활성화합니다.
트리거를 언마운트하면 대기 중인 호버 작업이 취소되고 유지되는 표시 상태가
초기화됩니다.

트리거는 항상 네이티브 노드에 설명을 노출합니다. 표시된 텍스트는 Tooltip 역할을
가지며 Tab 스톱이 없습니다. 위치 지정, 창 가장자리 고정, 그리기는 GPUI의 네이티브
툴팁 레이어가 소유하며, 이 컴포넌트는 포커스/호버 수명 주기를 추가합니다. 마운트된
Escape 구독은 해당 창에 속하며, 다른 툴팁을 닫을 수 있는 전역 지우기 작업을 실행하지
않습니다.

`.content(|window, cx| ...)`는 보이는 텍스트를 제목과 흐린 세부 줄, 또는 레이블과
키캡 같은 비상호작용 리치 콘텐츠로 대체합니다. 빌더는 보이는 표면이 렌더링될 때마다
실행됩니다. 일반 텍스트 설명은 계속 트리거의 네이티브 설명이자 표면의 Tooltip
이름이므로, 리치 콘텐츠가 보여 주는 내용과 동등한 요약으로 유지합니다. 리치 콘텐츠는
Tab 스톱을 추가하지 않습니다. 포인터가 트리거를 떠나면 툴팁이 닫히므로, 포커스
가능하거나 클릭 가능한 컨트롤을 그 안에 넣으면 안 됩니다. 상호작용 가능한 미리보기는
HoverCard나 Popover에 속합니다.

상호작용 가능한 툴팁 콘텐츠, 터치 길게 누르기 동작, 구성 가능한 프로바이더는 이
계약에 포함되지 않습니다. 예제는 기존 Edit session 버튼을 리치 제목과 세부 줄로
감싸므로, 같은 버튼이 설정 Dialog를 열고 포커스가 돌아올 대상으로 남습니다.
