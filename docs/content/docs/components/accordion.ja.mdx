`AccordionState` は、固定された順序付きの `AccordionItem::new(value,
label)` エントリのコレクションを保持します。値は一意でなければなりません。初期状態はすべて折りたたまれており、
`.default_open([value])` で有効なエントリを開きます。複数のパネルを同時に開くには
`.multiple(true).default_open(["general", "details"])` を使用します。デフォルトは有効な項目を指す必要があり、
単一展開モードで異なるデフォルトを複数指定すると設定エラーとなりパニックします。利用できないエントリには
`.disabled(true)` を指定します。

ヘッダーとパネルを `Accordion::new(id, &state)` で囲み、各 `AccordionHeader::new(&state, index)` を
対応する `AccordionPanel::new(&state, index)` とコレクションの順序どおりに組み合わせます。各ペアの配置には通常の GPUI コンテナを使用できます。
ルートはフォーカススコープとキーボード処理を提供しますが、レイアウトや外観は決定しません。

ヘッダーにはネイティブの見出しとボタンが含まれます。子要素とスタイルはボタンに適用されます。見出しレベルを 3 から変更するには
`.heading_level(level)` を使用します。
ヘッダーの内側にはインタラクティブでないコンテンツのみを置いてください。インジケーターの描画はアプリケーションが行い、
`is_open(index)` で開いているヘッダーと閉じているヘッダーを区別します。

| ヘッダー上の入力 | 動作 |
| --- | --- |
| クリック / Enter / Space | このパネルを切り替えます。単一展開モードでは前のパネルも閉じます |
| Up / Down | 前 / 次の有効なヘッダーにフォーカスを移動し、端では反対側へ循環します |
| Home / End | 最初 / 最後の有効なヘッダーにフォーカスを移動します |
| Tab / Shift-Tab | 有効なヘッダーと開いているコンテンツを通常のドキュメント順に移動します |

矢印キーによるナビゲーションではパネルは展開されません。有効なヘッダーはすべて通常の Tab ストップです。ナビゲーションアクションは
ヘッダー自体にフォーカスがあるときだけ適用されるため、パネル内の Input は独自の Home/End と矢印キーの動作を保ちます。無効なヘッダーは
アクティブにならず、キーボードのフォーカス移動にも含まれません。

State のメソッドには `items`、`is_open`、`open_values`、`trigger_focus_handle`、
`panel_focus_handle`、`toggle(index, window, cx)`、`close(window, cx)` があります。元の項目順で開いている値を受け取るには
`AccordionEvent::Change(values)` を購読します。
空のベクターはすべてのパネルが閉じていることを意味します。`close` は開いているすべてのパネルを閉じます。
何も変化しない操作では追加のイベントは発行されません。利用側を再描画するには State を observe します。
カタログの Navigation ヘルプは `.multiple(true)` で 2 つの独立した回答をマウントするため、
コマンドの説明を開いてもアライメントの回答は保持されます。セッションの Help はデフォルトの単一展開の契約のままです。

パネルを閉じると、そのレイアウト、フォーカスストップ、アクセシビリティノードが削除されます。再マウント後も
フォーム値や子エンティティを保持したい場合は、アプリケーションのビューで保持してください。パネルはデフォルトでは、独自の Tab ストップを持たない名前付きリージョンです。
静的コンテンツ自体にフォーカスを与えたい場合は `.tab_stop(true)` を使用します。

プログラムによる変更でキーボードフォーカスを持つパネルが閉じられた場合、フォーカスは残っているヘッダーへ移動します。
セクションを切り替える場合は、新たに開いたヘッダーへ移動します。関係のないコントロールからフォーカスを奪うことはありません。パネルを削除する前にフォーカスを移動しておくと、
ネストされた Popover も閉じるライフサイクルを完了できます。Accordion ホスト全体を削除する場合は、
アプリケーションが残っているコントロールにフォーカスを当てる必要があります。

ライブラリは見出しレベル、ボタンのロール、expanded/disabled の状態、名前付きの
Region を出力します。ボタンとパネルを結ぶネイティブの controls/labelled-by 関係は明示的には出力されません。固定された GPUI API が
必要となる兄弟ノードの ID を公開していないためです。
