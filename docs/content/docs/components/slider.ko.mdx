`SliderState::new(min..=max, step, [values...], cx)`를 한 번 생성합니다. 값이
하나면 썸이 하나인 슬라이더가 되고, 값이 두 개면 범위를 나타내며, 그보다 많으면
순서가 있는 지점이 추가됩니다. 비어 있지 않은 컬렉션이 썸 개수를 고정합니다.
범위와 값은 유한해야 하고, `min < max`이며, `step`은 양수여야 합니다. 값은 범위
안으로 고정되고, 최솟값에서 시작하는 단계 격자에 맞춰집니다. 범위는 양 끝을
포함합니다.

`Slider::new(id, &state).accessibility_label(...)`를 이름이 있는 그룹이자 레일로
렌더링합니다. 트랙과 채움을 제공하고, 값마다 순서대로
`SliderThumb::new(&state, index).accessibility_label(...)`를 하나씩 제공합니다.
각 썸은 자신의 네이티브 Slider 역할, 포커스, 키, 값 액션을 소유합니다. 범위의 양
끝에는 "Trim start"와 "Trim end"처럼 서로 다른 이름을 지정합니다.
`percentage(index)`는 해당 썸의 위치를 0부터 1까지로 제공합니다. 루트의 경계가
이동 레일을 정의합니다. 썸의 중심을 루트의 해당 비율 위치에 두고, 애플리케이션의
썸 크기의 절반만큼 오프셋합니다. 예제는 넉넉한 높이의 히트 영역과 그 안 가운데에
놓인 얇은 트랙을 사용합니다. 라이브러리는 색상이나 컨트롤 크기를 강제하지 않습니다.

상태는 `values`, `min_value`, `max_value`, `step_value`, `percentage`,
`thumb_focus_handle(index)`, `is_disabled`를 노출합니다. 프로그래밍 방식의
갱신에는 `set_thumb_value(index, value, window, cx)` 또는
`set_values(values, window, cx)`를 사용하고, 사용자 상호작용을 제어하려면
`set_disabled(disabled, window, cx)`를 사용합니다. 비활성화된 동안에도
프로그래밍 방식의 갱신은 가능합니다. 개별 썸은 이웃 썸에서 멈추며 서로 정체성을
바꾸지 않습니다. 같은 값은 허용됩니다. 정규화된 값이 바뀌면
`SliderEvent::Change(values)`가 순서가 있는 전체 값을 한 번 보고합니다.
애플리케이션의 시각 요소를 갱신하려면 상태를 관찰합니다.

레일을 누르면 가장 가까운 썸을 선택하며, 드래그하는 동안에는 레일 밖으로 나가도
놓을 때까지 그 썸을 유지합니다. `axis(Axis::Vertical)`은 최솟값을 아래쪽에 두고,
가로 값은 논리적 방향을 따릅니다. 각 썸은 접근 가능한 이름, 방향, 현재 값, 단계,
그리고 이웃 썸에 의해 제한되는 숫자 범위를 노출합니다. 썸의 포커스 표현은
애플리케이션이 제공합니다.

| 입력 | 동작 |
| --- | --- |
| Left / Down | 한 단계 감소 |
| Right / Up | 한 단계 증가 |
| Home / End | 포커스된 썸을 허용되는 최솟값 / 최댓값으로 설정 |
| PageDown / PageUp | 열 단계 감소 / 증가 |
| Tab / Shift-Tab | 활성화된 각 썸을 값 순서대로 방문한 뒤 그룹을 떠남 |

비활성화된 슬라이더는 사용자 변경을 무시하며 Tab에서 건너뜁니다. 포커스된 상태에서
비활성화된 슬라이더는 Tab으로 떠날 수 있을 만큼 포커스 바인딩을 유지합니다.
세션 미리보기는 썸 하나를 사용하고, 카탈로그의 미디어 트림 컨트롤은 독립적인 양 끝
두 개를 사용하며 가로/세로 배치와 RTL 사이를 전환합니다.
