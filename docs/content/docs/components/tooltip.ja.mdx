---
title: Tooltip
description: "Button のホバー/フォーカス時の、プレーンテキストのネイティブな説明と、任意の操作できないリッチコンテンツ、遅延ホバー、Escape による閉鎖、ネイティブの Tooltip の配置に対応します。"
---

既存の Button のフォーカスハンドルとともに `TooltipState::new(&trigger_focus, window, cx)` を保持します。
`Tooltip::new(id, &state, description)` を描画し、
`.trigger(|button| ...)` で Button を設定します。これにより、アプリケーションの
操作ハンドラーとフォーカスの同一性が保たれます。Tooltip の通常の Styled メソッドは、
操作できないサーフェスを設定し、トリガーのビルダーはボタンの
外観を管理します。追加の初期化呼び出しやキーバインディングは必要ありません。

キーボードフォーカスではテキストがすぐに表示され、ポインターのホバーでは 500 ms 待ちます。離れると
保留中のホバーがキャンセルされます。ブラー、アクティブ化、ウィンドウの非アクティブ化、Escape は、
フォーカスを移さずに閉じます。Escape は、別のフォーカスまたは
ポインターの進入があるまで再表示を抑制します。まだ表示されていない保留中のヒントをキャンセルしても、Escape は
周囲のサーフェスが利用できる状態のままです。Enter と Space は引き続き Button を 1 回操作します。トリガーを
アンマウントすると、保留中のホバー処理がキャンセルされ、保持されていた表示状態がリセットされます。

トリガーは常に、ネイティブノード上で説明を公開します。表示されたテキストは
Tooltip ロールを持ち、Tab ストップはありません。GPUI のネイティブの Tooltip レイヤーが配置、
ウィンドウ端への制限、描画を担当し、このコンポーネントはフォーカス/ホバーのライフサイクルを追加します。
マウントされた Escape の購読はそのウィンドウに属し、
別の Tooltip を閉じてしまう可能性のあるグローバルなクリア操作は発行しません。

`.content(|window, cx| ...)` は、表示されるテキストを、見出しと控えめな詳細行、
またはキーキャップ付きのラベルなどの、操作できないリッチコンテンツに置き換えます。
ビルダーは、表示サーフェスが描画されるたびに実行されます。プレーンテキストの説明は
トリガーのネイティブな説明およびサーフェスの Tooltip の名前として残るため、
リッチコンテンツが示す内容と同等の要約にしてください。リッチコンテンツは Tab ストップを
追加しません。フォーカス可能またはクリック可能なコントロールを置かないでください。ポインターが
トリガーを離れると Tooltip は閉じます。インタラクティブなプレビューは
HoverCard または Popover に置きます。

インタラクティブな Tooltip の内容、タッチの長押しの動作、設定可能な
プロバイダーは、この契約に含まれません。サンプルは、既存の Edit
session ボタンをリッチな見出しと詳細行で包んでおり、同じボタンが
設定の Dialog を開き、復帰先のフォーカスの対象のままになります。
