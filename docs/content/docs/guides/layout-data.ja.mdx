Table、ScrollArea、Resizable は、再利用可能な構造とネイティブの動作を提供します。アプリケーションは、
データ、レイアウトの寸法、色、タイポグラフィ、セルの内容を所有します。
[two-style サンプル](https://github.com/andongmin94/gpui-deck/blob/main/crates/base/examples/two_styles.rs)は、これらを
Schedule タブで組み合わせ、周囲のフォームには ScrollArea を使用しています。

## スクロールエリア内のテーブル

列がビューポートを超える場合は、テーブルの幅または最小幅を明示的に設定してください。
ネイティブのサンプルは、合計 490 ピクセルの 3 つの固定列を、
両方の軸に対応した ScrollArea の中に置いています。周囲の設定フォームは縦方向にスクロールします。
ネストされたテーブルは、フォームの日付を変更したり、
無関係な兄弟要素をスクロールさせたりすることなく、横方向に移動できます。日付の選択と名前/プリセットの編集は、
他のコントロールと同じ保持された状態から、テーブルを更新します。

## 検証の範囲

重点的なテストは、列の配置、テーブルのメタデータ、インタラクティブなセルの子要素、
ネイティブのスクロールと表示、区切りのドラッグ/キーボード操作、そして
DatePicker から Resizable の plan へのサンプルのフローをカバーしています。既存の
CI も、Linux、Windows、macOS でネイティブのサンプルをビルドします。自動化された GPUI の
イベント/レイアウトのチェックでは、ネイティブの視覚、スクリーンリーダー、混在 DPI、
パフォーマンスの結果は確認できません。
