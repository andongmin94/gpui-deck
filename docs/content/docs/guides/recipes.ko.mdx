이 23개의 카탈로그 레시피는 재사용 가능한 애플리케이션 소스이며, 네이티브
[두 스타일 예제](https://github.com/andongmin94/gpui-design/blob/main/crates/base/examples/two_styles.rs)와
[카탈로그 예제](https://github.com/andongmin94/gpui-design/blob/main/crates/base/examples/catalogue.rs)가 사용합니다. Chart에는
공개 동작 계열을 위한 보조 화면 표현 레시피도 있습니다. 레시피는 GPUI
레이아웃을 기존 컨트롤과 조합하고, 색상, 간격, 크기는 소비자의 `Palette`나
애플리케이션이 제공하는 `Styled` 값에 둡니다.

## 애플리케이션에 복사하기

소스 CLI는 레시피를 전이적 레시피 의존성, 라이트/다크 토큰 소스,
모듈 선언, 라이선스, 필요한 에셋과 함께 복사합니다.

```sh
cargo run -p gpui-design-cli --locked -- list
cargo run -p gpui-design-cli --locked -- add data-table avatar --to ../my-app/src/ui
```

소비자에서 `mod ui;`를 선언하고 `ui::recipes::{DataTable, Avatar}`와
`ui::Appearance::Settings.palette()` 또는 `ui::Appearance::Compact.palette()`를 사용합니다.
[설치 가이드](/ko/docs/installation/)에 있는 Cargo 의존성을 사용합니다. CLI는 소비자의 매니페스트를
변경하지 않습니다. 빌드할 때 저장소의 현재 레시피 소스를 포함하며,
원격 레지스트리나 업데이트 서비스는 없습니다.

소비자 앱의 매니페스트에 다음 기능 선언을 유지합니다.

```toml
[features]
test-support = ["gpui-design/test-support"]
```

복사된 레시피 테스트는 이 소비자 기능으로 보호됩니다. 이 기능을 선언하면
테스트의 `cfg` 값도 Rust에 알려집니다. 기존 GPUI 테스트를 실행하려면 이 기능을 활성화합니다.

같은 디렉터리를 확장하려면 이름을 더 붙여 `add`를 다시 실행합니다. 기존 레시피와
팔레트 편집은 보존됩니다. 생성된 `mod.rs` 선언과
`recipes/.gpui-design`이 설치된 집합을 추적합니다. 이 스캐폴드가 편집되었다면
CLI는 쓰기 전에 멈추고 선언을 수동으로 추가하는 방법을 안내합니다.
충돌하는 새 파일도 거부됩니다. 복사된 소스는 애플리케이션의 소유입니다.

저장소를 업데이트한 뒤 `diff`를 실행하면 설치된 파일과 현재 CLI에 포함된
소스를 비교할 수 있습니다. `PATH`에서 Git을 실행할 수 있어야 합니다. 설치된 레시피
목록을 바탕으로 관리 대상 파일의 변경 및 누락을 표시합니다. 각 패치에서 `-`는
앱의 줄, `+`는 CLI에 포함된 줄이며 앱 파일은 그대로 유지됩니다.

```sh
cargo run -p gpui-design-cli --locked -- diff --to ../my-app/src/ui
```

수동으로 복사하려면 다음과 같이 합니다.

1. [`crates/base/examples/recipes`](https://github.com/andongmin94/gpui-design/blob/main/crates/base/examples/recipes)에서
   원하는 파일을 애플리케이션 모듈로 복사하고, 저장소의 라이선스 조건을 유지합니다.
2. 작은 [`mod.rs`](https://github.com/andongmin94/gpui-design/blob/main/crates/base/examples/recipes/mod.rs)를 따라
   복사한 모듈을 선언하고 타입을 다시 내보냅니다. 애플리케이션에 필요한 모듈만
   복사하고 그 모듈만 나열합니다.
3. [`presentation.rs`](https://github.com/andongmin94/gpui-design/blob/main/crates/base/examples/presentation.rs)를
   애플리케이션의 `recipes` 디렉터리 옆에 복사합니다. 이 파일에는 테스트된 예제가 쓰는
   실제 `Palette`와 두 화면 표현이 들어 있으며, Demo나 그 동작은 포함하지 않습니다.
   레시피의 상위 모듈에서 이를 선언하고 토큰을 노출합니다.

   ```rust
   mod presentation;
   pub(crate) use presentation::{Appearance, Palette};
   mod recipes;
   ```

   애플리케이션 뷰에서 `Appearance::Settings.palette()` 또는 `Appearance::Compact.palette()`를
   선택합니다. `use super::super::Palette` 같은 레시피 import는
   그대로 동작합니다. 복사한 토큰 값을 애플리케이션에 맞게 바꾸거나, Palette를
   기존 토큰 타입으로 대체합니다. AspectRatio는 팔레트를 받지 않으며, 소비자가
   시각 스타일을 제공합니다. Bubble과 Chart는 현재 자체적으로 복사 가능한 스타일을 유지합니다.
4. 그 애플리케이션 모듈에서 타입을 import합니다. 타입은 `pub(crate)` 가시성을 사용하며
   `gpui_design`에서 내보내지 않습니다. 추가 의존성은 필요하지 않습니다.

팔레트 모듈과 레시피는 라이브러리 export 바깥에 있는 애플리케이션 소스입니다.
CLI는 로컬 소스 배포를 제공하며, 이 시각 토큰은 전역 테마 프로바이더를
설치하지 않습니다. 상호작용 동작은 계속 라이브러리가 소유합니다.

일부 레시피는 다른 레시피 모듈을 조합합니다. 원하는 레시피와 함께 해당 모듈과
그 re-export도 복사합니다.

| 레시피 | 필요한 다른 레시피 모듈 |
| --- | --- |
| DataTable | InputGroup, EmptyState, Pagination |
| Message | Typography (`Paragraph`) |
| Trace | Typography (`Paragraph`) |

## 검증 범위

기존 조합 테스트 스위트는 네이티브 예제와 같은 레시피 모듈을 실행합니다.
명령 검색 흐름은 빈 상태 복구를 다루고, 날짜 선택기 흐름은 그룹화된
월 버튼의 순회와 활성화를 다룹니다. 정적인 형태와 팔레트 값에는 별도의
테스트 스위트가 없습니다. 기존 필드/프리셋 흐름은 누락된 이름 복구,
읽기 전용 입력의 비활성화된 애드온, 긴급 인라인 의미,
Item의 유지되는 미리보기/편집 동작을 다룹니다. 날짜 선택기
흐름은 일반 일정 알림이 Note로 남는지도 확인합니다. 기존
3개 플랫폼 CI는 계속해서 실제 소비자 조합과 네이티브
컴파일을 확인합니다. Linux는 격리된 레시피 테스트를 추가로 실행합니다. Windows와 macOS는
같은 조합 대상에서 `two_styles::recipes::` 테스트를 제외해, 실제 애플리케이션
흐름은 유지하면서 레시피 전용 확인의 반복을 피합니다. 추가 조합 흐름
하나가 프리셋 테이블의 정렬, 필터/빈 상태 복구, 페이지 경계,
안정적인 ID 액션, 유지되는 선택을 다룹니다. 별도의 데이터
테스트 프레임워크나 중복된 플랫폼별 흐름은 없습니다. 이 결과는
네이티브 스크린리더, IME, 시각, 성능 검증을 보장하지 않습니다.

기존 미리보기 흐름은 이름 있는 Spinner 렌더링, 장식용이며 포커스를 받지 않는
Skeleton, GPUI 모션 감소 렌더링, 초기화 취소, 백분율 채움 복원,
디스클로저가 닫힐 때 표시기 제거도 다룹니다. 로딩 레시피는 테스트 함수나
CI 작업을 추가하지 않습니다. 애니메이션 스케줄링은 여기서 두 번째 테스트 컨트롤러를
두지 않고 GPUI의 책임으로 남습니다.

기존 Help 흐름은 조합된 Breadcrumb 상위 항목 액션과 함께, Kbd의 읽을 수 있는
기호 키 이름과 새 포커스 스톱이 없음을 확인합니다. 컨텍스트 메뉴 흐름은
키캡으로 표시되는 기존 단축키를 실행합니다.
이 정적 키 힌트를 위한 별도의 키 바인딩 테스트 컨트롤러,
팔레트 스위트, CI 작업은 없습니다. 네이티브 스크린리더 음성과
데스크톱 시각 렌더링은 별도의 검증 작업으로 남습니다.

미디어 레시피는 같은 조합 대상 안에 집중된 회귀 테스트 두 개를 추가합니다.
Avatar는 없음, 대기, 실패, 로드됨, 지워짐 상태의 이미지 소스를 실행하면서
네이티브 이름, 포커스 중립성, 고정된 형상을 확인합니다. 로드 경로는
번들된 SVG를 디코딩합니다. AspectRatio는 두 가지 컨테이너 너비, 너무 큰
콘텐츠, 프레임 밖의 포인터 클리핑을 실행합니다. 기존 프리셋 흐름은
유지되는 선택이 미리보기의 아트워크, 프레임 비율, 세션 이름을 결정하면서
기존 트리거와 닫기 동작을 보존하는지 확인합니다. 이 확인은
원격 이미지 전송, 네이티브 스크린리더 음성, 데스크톱 시각 렌더링,
성능 측정을 보장하지 않습니다.

Sheet 커버리지는 가장자리 배치, 일반 및 좁은 뷰포트 너비,
고정된 헤더/푸터 형상, 본문 스크롤, 하위 요소 포커스 표시,
유지되는 폼 상태와 함께 닫고 다시 여는 동작을 실행합니다. 또한
공유 Dialog의 배경 휠 처리를 실행해 아래 콘텐츠가 스크롤되지 않게 하는지 확인하고,
좁은 창에서 Select를 열어 자식 팝업의 가로 경계를 확인합니다.
중첩 모달 확인은 최상위 대화상자의 포커스 가두기와 휠 격리,
Sheet가 열린 상태에서 그 대화상자를 닫는 동작,
Sheet를 거쳐 원래 트리거로 돌아가는 동작을 다룹니다. 이는 기존 GPUI 테스트 컨텍스트에서의
레이아웃 및 상호작용 확인이며, 그 범위는 네이티브 스크린리더, 플랫폼 IME,
데스크톱 시각 검증을 보장하지 않습니다.

Typography 확인은 시각적 크기와 무관한 네이티브 제목 수준,
완전한 접근 가능한 이름, Paragraph와 Code 역할, 텍스트에 포커스 스톱이
없음을 다룹니다. 레이아웃 커버리지는 긴 텍스트와 코드를 두 화면 표현의
일반 및 좁은 너비에서 사용합니다. Help 소비자는 기존 계층 구조,
상위 항목 액션, 키보드 순회를 보존합니다. 조합 대상은 예제의 렌더 스택
회귀를 확인하기 위해 1.5 MiB 테스트 스레드 스택으로도 실행됩니다.
이는 네이티브 메타데이터, 레이아웃, 시뮬레이션 입력 확인이며, 스크린리더
음성, 플랫폼 IME 동작, 데스크톱 시각 결과에는 별도의
검증이 필요합니다.

Sidebar는 Settings 소비자의 기존 조합 흐름에서 실행되며,
별도의 후보 픽스처는 없습니다. 이 흐름은 명시적 활성화,
비활성화된 항목, 현재 섹션 의미, 유지되는 값, 일반적인 포커스
순회, 좁은 창에서 쌓이는 레이아웃을 확인합니다. Compact의 TabList 동작은
계속 실제 소비자 흐름이 다룹니다. 현재 페이지 확인은 Button의 네이티브 메타데이터 계약이
소유하고, 포커스 중립적인 프로그램 선택과 변경 이벤트는 TabsState의 핵심 회귀 테스트가
소유합니다.

Code Block 커버리지는 빈 콘텐츠와 여러 줄 콘텐츠, Unicode, 완전한 코드
이름, 보존된 줄 끝, GPUI 테스트 클립보드를 통한 정확한 전체 텍스트 복사를
확인합니다. 레이아웃 확인은 두 화면 표현, 좁은 너비, 긴 줄,
긴 본문을 실행합니다. 소비자 흐름은 복사된 JSON의 현재 설정,
키보드 입력과 순회, 코드 스크롤 끝, 상위
Sheet 스크롤 범위로부터의 격리를 검증합니다. 클립보드 단언은 테스트 플랫폼에서만 실행되며
사용자의 데스크톱 클립보드 서비스는 실행하지 않습니다. 조합 대상은
1.5 MiB 스택 확인도 유지합니다. 네이티브 클립보드 통합, 스크린리더
음성, IME, 데스크톱 시각 관찰은 별도의 검증 작업으로 남습니다.

Marker 커버리지는 의미 있는 단일 레이블, 장식용 구분자 생략,
마커를 지나는 일반 포커스 순회를 확인합니다. 레이아웃 확인은 긴 한국어와
영어 레이블, 좁은 너비, 두 화면 표현을 실행합니다. Schedule 확인은
현재 선택된 날짜를 이동되거나 취소된 달력 커서와 구분하고,
기존 키보드 흐름을 보존하며, 선택이 바뀌거나 지워질 때 경계를
갱신합니다. 이는 메타데이터, 레이아웃, 시뮬레이션 입력 확인이며, 네이티브
스크린리더 음성, IME, DPI, 데스크톱 시각 관찰은 별도의
검증 작업으로 남습니다.

Message의 집중 레시피 확인은 Comment/Label/Paragraph 계층 구조,
제공된 각 텍스트의 접근 가능한 이름이 한 번만 나타나는지, 명시적 줄바꿈, 긴
한국어와 영어 콘텐츠, 두 화면 표현의 좁은 너비 줄바꿈을 다룹니다.
활성화와 비활성화 동작은 Button 자체 테스트가 다룹니다. Schedule 소비자는
공유된 메모 값, 로컬 편집 메타데이터, 빈 상태 전환,
Edit note 포커스, 기존 Sheet 스크롤과 닫기를 확인합니다. 이는 헤드리스
메타데이터, 레이아웃, 입력
확인이며, 네이티브 스크린리더 음성과 데스크톱 시각 검증은
별도로 남습니다.

Attachment의 집중 레시피 확인은 전체 파일 이름으로 된 이름과 결합된
메타데이터 설명이 자식 의미 중복 없이 제공되는지, 긴 한국어와 영어 파일 이름,
좁은 너비 줄바꿈, 두 화면 표현을 다룹니다. 제공된 액션은 Button의
독립적으로 테스트된 활성화와 비활성화 동작을 유지합니다. Help 소비자는
바이트 수가 현재 UTF-8 JSON을 따르는지, Inspect JSON이
기존 코드 포커스 대상에 도달하는지, 그리고
CodeBlock이 완전한 복사와 스크롤 동작을 유지하는지 확인합니다. 클립보드 단언은
GPUI 테스트 클립보드로 한정됩니다. 네이티브 파일 접근, 스크린리더 음성,
데스크톱 시각 관찰은 이 확인으로 보장되지 않습니다.

Trace의 집중 레시피 확인은 요약 이름 지정, 펼침 메타데이터, 이름 있는
Region과 Paragraph 계층 구조, 닫힌 콘텐츠 제거, 그리고 두 화면 표현의 좁은 너비에서
긴 요약과 세부 내용의 줄바꿈을 다룹니다. 활성화, 비활성화된 트리거 동작,
닫힐 때의 포커스 복귀는 Collapsible의 핵심 테스트가 소유합니다. 제공된
액션은 기존 Button 계약을 사용합니다. Help 소비자는 현재 폼
값,
디스클로저 유지, Close details 액션, 주변 Sheet 스크롤과
포커스를 확인합니다. 조합 대상은 1.5 MiB 스택 확인을 유지합니다. 이 테스트는
네이티브 메타데이터, 레이아웃, 시뮬레이션 입력을 실행하며, 데스크톱 렌더링,
스크린리더 음성, IME, 성능에는 여전히 별도의 검증이 필요합니다.
