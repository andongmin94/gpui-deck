[두 스타일 예제](https://github.com/andongmin94/gpui-design/blob/main/crates/base/examples/two_styles.rs)는 같은
설정 동작을 촘촘한 다크와 넉넉한 라이트 화면 표현으로 조합합니다.
Session actions 메뉴와 요약의 ContextMenu는 Dialog를 열거나, 애플리케이션 값을
토글하거나, AlertDialog를 통해 미리보기 초기화를 요청할 수 있습니다. HoverCard는
현재 프리셋, 날짜, 메모 상태를 미리 보여 주고, 프리셋 버튼은 평소의 설정 동작을
그대로 유지합니다. Collapsible은 미리보기 컨트롤을 담습니다.
Search commands는 Dialog 안에서 Command 쿼리와 결과 목록을 엽니다. 두 메뉴는
같은 애플리케이션 액션을 디스패치합니다. Separator는 콘텐츠 영역 사이를
의미적으로 구분하고, 설정 폼에는 유지되는 여러 줄 메모가 있습니다.
Compact는 활성 패널과 함께 Preferences, Help, Schedule, Presets 탭을 사용합니다.
Settings는 [Sidebar 레시피](../recipes/sidebar.mdx)와 현재 섹션을 위한 이름 있는
Region을 사용합니다. Help에는 Accordion이 있고, 키보드 섹션은 비모달
Popover로 가이드를 엽니다. Breadcrumb은 그 가이드의 위치를 보여 주고,
애플리케이션이 소유하는 [Kbd 레시피](../recipes/kbd.mdx)는 기존 키보드 컨트롤을 표시합니다.
모든 스타일은 예제에 있습니다.

`gpui_design::init(cx)`를 호출하고 창을 `gpui_design::Root` 안에 둡니다.
상태 엔티티와 관찰 구독은 뷰에 보관합니다. 예제는
전체 설정과 애플리케이션이 소유하는 스타일을 보여 줍니다.

## 검증

기존 GPUI 테스트 프레임워크는 선택 및 비활성화 메타데이터, 방향,
포커스 순회, 비활성 패널, 팝업 닫기, 명령 디스패치, 그리고 두 화면 표현과
카탈로그에 걸친 대표적인 조합 흐름을 확인합니다. 조합 테스트는 Dialog를 여는
명령, 펼치지 않는 헤더 내비게이션, 열린 Popover가 있는 패널의 접기,
디스클로저 마운트, 명시적인 미리보기 초기화 확인을 다룹니다.
소비자 흐름은 명령 검색에서 여러 줄 설정 폼으로 이어지는 흐름,
일반 및 비활성화 필드의 Tab 순회, 유지되는 메모를 다룹니다.
또한 툴팁 트리거, Field 레이블/피드백, Dialog 안의 검색 가능한 프리셋 선택을
다루며, 여기에는 쿼리 취소와 선택 유지가 포함됩니다.
기존 흐름은 그 Dialog를 여는 키보드 및 포인터 컨텍스트 메뉴 명령과,
평소 액션과 포커스 복귀 대상을 유지하는 HoverCard 트리거도 실행합니다.
체크 명령은 같은 흐름을 사용해 두 메뉴 호스트에서 현재 애플리케이션 값과
변하지 않은 액션/포커스 동작을 검증합니다.
프리미티브 테스트는 지점 배치와 포인터 미리보기 타이밍을
각각을 소유하는 계층에서 다룹니다.
Breadcrumb의 검증 범위는 네이티브 navigation/list/item 역할,
현재 페이지 메타데이터, 그리고 기존 Help 흐름의 조합된 상위 항목 액션입니다.
이 흐름은 정적 키 힌트가 포커스를 기존 컨트롤에 남겨 두는지도 확인합니다.
이 계약은 네이티브 스크린리더 안내나 경로와 키캡의 시각적 외형을 보장하지 않습니다.
전체 테스트 스위트는 격리된 레시피 확인을 포함해 Linux에서 한 번 실행됩니다. Windows와
macOS는 레시피 전용 테스트를 제외하고 실제 소비자 조합 흐름을 실행하며,
세 플랫폼 모두 네이티브 예제를 빌드합니다. 이는 데스크톱에서의
네이티브 IME, 스크린리더, DPI, 시각 확인을 대체하지 않습니다.
