**2026-11-21**에 확인한 참조 카탈로그:
[shadcn/ui All Components](https://ui.shadcn.com/docs/components).
주 카탈로그에는 **66개 항목**이 있으며, 아래에 각각 한 번씩 나열합니다. 별도의
AI Elements 카탈로그는 이 비교 대상이 아닙니다. 주 카탈로그에 이미 있는 대화
컴포넌트는 계속 포함합니다.

GPUI Design은 **42개의 공개 라이브러리 패밀리와 23개의 복사 가능한 화면 표현/조합
레시피**를 문서화하며, 이를 통해 **65개의 서로 다른 구현**을 제공합니다.
나머지 카탈로그 항목인 Native Select는 GPUI에서 명시적으로 **Select에 매핑**됩니다.
아래 **66개 참조 항목 모두가 구현된 범위나 플랫폼 매핑을 가지며**, 할당되지 않았거나
Pending 상태로 남은 항목은 없습니다.

이는 카탈로그 커버리지이며, shadcn/ui와의 완전한 기능 동등성이 아닙니다. 각 계약에는
명시적인 한계가 있으며, HTML 전용 매핑은 브라우저 컨트롤이나 운영체제 선택기를 구현하지
않습니다. 이 수치는 성능, 접근성 적합성, 네이티브 데스크톱 검증 완료 여부를 측정하지
않습니다.

목표는 비교 가능한 애플리케이션 구축 범위입니다. 공유 동작은 라이브러리에 두고,
재사용 가능한 화면 표현과 화면 조합의 소스는 애플리케이션에 속합니다. 아래 그룹은
shadcn의 내부 아키텍처가 아니라 우리의 구현 책임을 설명합니다. `two_styles`와 `catalogue`
네이티브 예제는 재사용 가능한 [화면 표현 레시피](./guides/recipes.mdx)를 사용합니다. 레시피
소스는 이 저장소에서 배포되며, 로컬 소스 CLI가 레시피, 의존성, 토큰, 라이선스를 소비자가
소유하는 모듈에 설치합니다. 원격 레지스트리는 제공하지 않습니다.

## 상태의 의미

- **Available:** 공개 패밀리와 소비자 예제가 명시된 범위를 다룹니다.
- **Recipe:** 재사용 가능한 애플리케이션 소스와 동작하는 소비자 예제가 명시된 화면
  표현을 다룹니다. 레시피는 라이브러리의 공개 export 밖에 있습니다.
- **Mapped:** 명시적인 GPUI 플랫폼 대응물이 네이티브 애플리케이션의 필요를 충족합니다.
  브라우저 전용 계약은 별칭 뒤에 숨기지 않고 문서화합니다.

## 동작과 시맨틱 기반

이 컴포넌트들은 상호작용, 상태, 포커스, 또는 재사용 가능한 시맨틱 계약을 소유합니다.
외형은 계속 애플리케이션이 소유합니다. 구현된 정확한 API는
[폼 가이드](./guides/forms.mdx),
[내비게이션과 오버레이 가이드](./guides/navigation-overlays.mdx),

## 화면 표현과 조합 레시피

이 항목들은 주로 일관된 시각 기본값과 적절한 시맨틱을 갖춘 재사용 가능한 소스 조합이
필요합니다. 기존 GPUI 레이아웃과 컨트롤이 작업을 맡아야 하며, 시각적 이름마다 새로운
상태 컨트롤러를 추가할 필요는 없습니다.
배포되는 레시피는 `crates/base/examples/recipes`에 있으며, 시각 스타일은 소비자에게
두고, 네이티브 two-style 예제에 조합됩니다.

## 더 큰 결합 기능

이 항목들은 하위 수준의 동작과 화면 표현을 결합해 더 완전한 워크플로를 만듭니다.
여전히 범위 목표의 일부이며, 같은 입력, 팝업, 포커스, 스크롤 기구를 독립적으로 다시
구현하기보다 동작하는 공유 컴포넌트에서 성장해야 합니다.

| 카탈로그 항목 | 상태 | 현재 범위 또는 공백 |
| --- | --- | --- |
| Attachment | Recipe | 전체 파일 이름으로 명명된 정적 네이티브 Group, 보이는 미디어 유형/크기 설명, 선택적 기존 액션. Help는 CodeBlock과 같은 문자열에서 메모리 내 JSON 메타데이터를 만들며, Inspect JSON은 해당 코드 뷰포트에 포커스를 줍니다. 서식과 액션 동작은 애플리케이션에 속합니다. 파일 접근, 업로드/다운로드, 진행률, 미리보기 렌더러, 컨테이너 포커스 스톱은 없습니다. |

| Trace | Recipe | 유지되는 Collapsible 상태 위에서 애플리케이션이 제공하는 요약, 이름이 있는 읽기 전용 Paragraph 세부 내용, 선택적 기존 액션. 공유 Button 활성화, expanded/disabled 메타데이터, 활성 콘텐츠만 렌더링, 닫힐 때의 포커스가 보존됩니다. Help는 기록된 작업이 아니라 현재 폼 값을 보여줍니다. 실행 기록, 스트리밍, 파서, 별도의 펼침 상태, 스크롤 컨트롤러는 없습니다. |

## 완료 기준과 현재 작업

목표는 네이티브 GPUI에서 동작, 접근성, 시각 기본값, 소스 배포 전반에 걸친 shadcn/ui
수준의 사용성입니다. 66개 항목 카탈로그는 범위 커버리지만 셉니다. 이는 완료율이나
출시 준비 상태에 대한 주장이 아닙니다. 위의 `Available`, `Recipe`, `Mapped`는 동등성이
완성되었다는 뜻이 아닙니다.

작업은 별도의 진행 보고서 없이 이곳과 Git에서 추적합니다. 기능은 문서화된 소비자 계약이
구현되고, 네이티브 예제에서 실행되고, 적절한 기존 테스트 계층에서 다뤄지고, 정확하게
문서화되었을 때 완료됩니다. 플랫폼 관찰은 자동화된 검사와 별도로 기록합니다.

| 우선순위 | 작업 | 종료 조건 | 현재 상태 |
| --- | --- | --- | --- |
| 1 | 기존 정확성과 핵심 상호작용 공백 | 관찰된 실패를 수정하고, 단일 선택 ToggleGroup과 다중 열림 Accordion을 지원하며, 네이티브 값, 키보드/포인터 활성화, 비활성화 상태, 닫힐 때의 포커스를 검증 | 집중된 테스트와 카탈로그 소비자로 구현됨 |
| 2 | 남은 공통 컴포넌트 계약 | 공식 컴포넌트 예제를 위의 각 범위와 대조해 점검하고, 수동 Tabs 활성화, 팝업 side/alignment, 범위 입력/날짜 선택, 소비자가 요구하는 나머지 선택/테이블/내비게이션 기능을 집중된 테스트 및 예제와 함께 구현 | 나열된 공통 공백 구현됨. 핵심 유지 값, 조합, 소스 배포, 네이티브 메타데이터 점검 완료. 기능 한계는 범위 표에 명시적으로 남아 있음 |
| 3 | 시각 기본값과 접근성 | 일관되게 보이는 키보드 포커스, 비활성화/호버/선택/오류 상태, 재사용 가능한 애플리케이션 소유 토큰, 좁은 창 레이아웃, 사용 가능한 라이트/다크 화면 표현 | 카탈로그 포커스와 복사 가능한 라이트/다크 토큰 구현됨. 네이티브 Calendar/Sheet 스모크 수행. 이름 없는 카탈로그 버튼/링크를 회귀 커버리지와 함께 수정. 더 넓은 네이티브 검토는 대기 중 |
| 4 | 소스 배포와 개발자 경험 | 작고 완전한 starter, 컴파일 가능한 공개 예제, 명시적으로 지원되는 API 경계, 레시피 의존성과 토큰을 해결하는 소스 복사 워크플로 | Starter, doctest 게이트, 애플리케이션 토큰, 의존성을 인식하는 소스 CLI 구현됨. 지원되는 입력/컨트롤 경계와 소비자 테스트 feature 문서화. 사용하지 않는 ThemeAppearance 제거 |
| 5 | 출시 검증 | 기존 포매팅, 린트, 전체 동작 스위트, 네이티브 예제 빌드 통과. 대표적인 네이티브 IME, 스크린리더, DPI, 시각 흐름에 대한 플랫폼별 관찰 확보 | 완료되지 않음 |

각 리비전의 Rust 검사와 네이티브 예제 빌드 결과는 [Verify 워크플로](https://github.com/andongmin94/gpui-design/actions/workflows/verify.yml)에서 확인할 수 있습니다. [Docs 워크플로](https://github.com/andongmin94/gpui-design/actions/workflows/docs.yml)는 설치 예제의 GPUI 버전, WebAssembly 미리보기 빌드와 사이트의 브라우저 테스트를 확인합니다.

shadcn의 공식 예제가 다루는 "제공하지 않음" 한계는 이제 명시적인 경계 안에서
구현되었습니다. 입력된 날짜는 임의의 자연어가 아니라 ISO와 몇 가지 영어 상대 표현을
받으며, 레이아웃 저장은 애플리케이션에 남습니다. 터치 길게 누르기는 시뮬레이션된 GPUI
터치 이벤트로만 실행했으며, 터치 하드웨어에서는 시도하지 않았습니다. Carousel 자동 재생,
Sidebar 레일, ControlField, AvatarGroup은 헤드리스 및 조합 커버리지만 있으며, 네이티브
외형은 관찰하지 않았습니다.

기존 테스트는 문서화된 선택/오버레이 계약, 유지 값 설정자, 사용할 수 없는 Calendar
날짜/RTL, 테이블 선택/표시 여부, Sidebar 닫힘, 네이티브 읽기 전용 메타데이터, 여러 줄/스크롤된
UTF-16 지점 조회, 모달 플래그(비모달 Popover 포함), 그리고 장식용 배경 없는 배경
포인터/휠 격리를 다룹니다. 조합 검사에는 320/980 px의 Sidebar와 320×520/980×840의 모든
Sheet 가장자리가 포함됩니다.

네이티브 Windows 관찰은 starter 편집/Tab/Enter, Selection 뷰와 범위 팝업, 사용할 수 없는
일요일의 포커스/활성화 차단, 위쪽 Sheet 레이아웃/본문 스크롤/포커스 반환을 다룹니다.
UI Automation 이름을 검사하고, 없는 곳은 수정했으며, Navigation/Selection에서 다시
관찰했습니다. 이는 제한된 시각 및 메타데이터 관찰이며, 스크린리더 음성 검증이 아닙니다.

이후의 네이티브 Windows 점검(QHD 모니터 1대, 100% 배율로 가정, 라이트 및 다크 화면
표현)에서는 카탈로그의 line, 누적 bar/area, pie, donut, radar 차트, radar 포인터 검사,
뷰당 한 개와 두 개 슬라이드에서 Next를 사용한 Carousel, Component APIs로 이동하는
Breadcrumb 생략 메뉴를 관찰했습니다. `two_styles`에서는 Item 미디어/헤더/푸터 레이아웃,
풍부한 Edit session 툴팁, 입력된 날짜("in 3 days"는 적용되고 "2026-02-30"은 Field 오류를
표시), 플랜 패널의 약 96 px 하한에서 멈추는 일정 구분선을 관찰했습니다. 그 점검에서
radar 방사형 레이블을 테두리에서 떨어지도록 옮기고, Item 미디어의 글꼴에 의존하는 녹화
글리프를 그린 점으로 교체했습니다.

아직 남은 작업: 실제 한국어/CJK IME 조합/후보/확정/취소, 스크린리더 음성과 액션, 혼합
DPI, 터치 하드웨어, 나머지 데스크톱 시각 검토. 자동화 도구는 한/영 키를 지원하지 않으므로
해당 네이티브 흐름은 한국어 모드를 수동으로 선택해야 합니다. 헤드리스 핸들러 테스트는
네이티브 IME 동작을 입증하지 않습니다. 전체 목표는 아직 완료되지 않았습니다.
공식 [Accordion multiple 예제](https://ui.shadcn.com/docs/components/base/accordion#multiple),
[Toggle Group 사용법](https://ui.shadcn.com/docs/components/base/toggle-group#usage),
[Slider range](https://ui.shadcn.com/docs/components/base/slider#range),
[Calendar](https://ui.shadcn.com/docs/components/base/calendar),
[Combobox](https://ui.shadcn.com/docs/components/base/combobox)가 구체적인 동작 참고
자료를 제공합니다. [Data Table 가이드](https://ui.shadcn.com/docs/components/base/data-table)와
[Sidebar](https://ui.shadcn.com/docs/components/base/sidebar)는 선택, 열 표시 여부, 접기/그룹
조합 참고 자료를 제공합니다.
[Sheet 참고 자료](https://ui.shadcn.com/docs/components/base/sheet)는 네 가장자리 배치를
설명합니다. Calendar의 사용할 수 없는 날짜 포커스는
[APG 비활성화 그리드 지침](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/#focusability-of-disabled-controls)을
따르며, 애플리케이션 조건자와 주 순서는 명시적인 네이티브 계약으로 남습니다.
[소개](https://ui.shadcn.com/docs)와
[테마 가이드](https://ui.shadcn.com/docs/theming)도 시각 기본값과 소스 재사용을 목표의
일부로 삼습니다. 브라우저 전용 API는 추가 별칭이 아니라 명시적인 네이티브 대응물이
필요합니다.

세션 컨트롤에는
`cargo run -p gpui-design --example two_styles --locked -- settings`를, 내비게이션,
OTP/Drawer/Toast, 미디어/차트, 대화/설문 흐름에는
`cargo run -p gpui-design --example catalogue --locked`를 사용합니다.

네이티브 IME, 스크린리더, 시각, DPI, 성능 관찰은 자동화된 검사와 별도로 남습니다.
수행하지 않은 플랫폼 검증은 완료로 간주하지 않으며, 측정 없이 성능을 주장하지 않습니다.

## 참고 자료와의 차이

[shadcn 소개](https://ui.shadcn.com/docs)는 소스 소유권, 조합, 배포, 시각 기본값을
설명합니다. 비교 가능한 범위에는 헤드리스 동작뿐 아니라 소비자를 위한 레시피도
포함됩니다.

현재 [Combobox](https://ui.shadcn.com/docs/components/base/combobox) 문서는 편집 가능한
자동 완성과 추가 선택 변형을 다룹니다. 여기의 구현은 그룹으로 묶인 단일/다중 선택과 항목
교체를 제공합니다. 애플리케이션은 칩 화면 표현과 비동기 요청 소유권을 유지하며, 이
기능들은 컴포넌트를 추가하기보다 같은 패밀리를 심화합니다.
[Command](https://ui.shadcn.com/docs/components/base/command)는 두 번째 독립 명령 엔진을
요구하지 않고 대화상자 조합을 포함합니다.

[Date Picker](https://ui.shadcn.com/docs/components/base/date-picker)는 캘린더와 팝업
부분으로 조합됩니다.
[Data Table](https://ui.shadcn.com/docs/components/base/data-table)은 공유 기반 위에서
애플리케이션별 테이블을 만드는 가이드입니다.
[Native Select](https://ui.shadcn.com/docs/components/base/native-select)는 브라우저 HTML
컨트롤을 명시적으로 감싸므로, 그 플랫폼 계약은 조정이 필요합니다.
